# 引き継ぎエージェント向け指示

目的は、京都・三浦の評価で作ったコマ地図の省略処理を別アプリへ移植できるようにすること。まず受領先リポジトリのAGENTS.mdと現在のユーザー指示を読み、この資料と衝突する場合は受領先の権限・作業範囲を優先する。このファイル自体はpush、マージ、公開、AWS操作を許可するものではない。

1. README.md、docs/INPUT_CONTRACT.md、docs/INTEGRATION.md、docs/EVALUATION.md、docs/REPRODUCIBILITY.mdを読む。
2. PROVENANCE.jsonの対象コミットと、受領先の現コミットを比べる。構造が変わっていれば対応表を更新し、参照用のtarget-referenceで本体を上書きしない。
3. verify_bundleとテストを先に実行する。元データと元ソースのsnapshotは変更せず、移植先に必要なコードをコピーして編集する。
4. 全交差点→道なり候補→次の表示コマとの比較→類似なら復帰→区間を再分割して繰り返す→最終採番、という順序を維持する。ペアの推論結果だけでコマを削除しない。
5. 開始・終了・CP/stop・折り返し・必須右左折・手動編集・held/不明データを保護する。直進信号は残すが、その信号だけを理由に残った次コマについては類似比較を行わず、そこで比較区間を区切る。右左折信号等へ例外を拡張しない。
6. 枝は中心から外向きのWGS84折れ線、headingは北0・時計回りのrad。直前のルートから8mで進入方向を求める。枝は最大28m、次の実交差点で止める。本数・左右・進入路・短い枝を保持する。SVG座標や最短端点から逆推定しない。
7. 正解ラベル、評価者、地域、絶対座標、ID、現行ルール出力をAI特徴量に混ぜない。座標は相対形状の計算とグループ分割にのみ使用する。
8. sourceの350特徴量の順序とfloat32木比較を維持し、goldenで確認する。画像を入力する深層モデルではなく、数値特徴量＋RandomForestのJSONである。
9. models/corrected-candidateは候補。旧OOF再集計の1.5%をそのモデルや受領先アプリの精度として表示しない。独立⑧の問題・回答・予測は含めていない。必要なら評価者に別途依頼し、学習には混ぜない。
10. 起動方法、変更箇所、残る互換性差、既知の不正解、テスト結果を受領者に報告する。AI障害や不明形状は保持側へ倒す。手動確認とallモードを残す。
