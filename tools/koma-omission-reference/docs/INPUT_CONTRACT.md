# 入力・出力・特徴量契約

## ペア入力

```json
{
  "candidate": {"center":{"lat":35,"lon":139},"heading":0,"branches":[[]]},
  "target": {"center":{"lat":35,"lon":139},"heading":0,"branches":[[]]},
  "entryIndex": 0,
  "targetEntryIndex": 0
}
```

上はキーの説明用であり、空のbranchesは無効です。有効な実例はexample-pairs.jsonとtests/golden.json。`pair: {modelInput: {candidate,target},...}` 形式にも対応します。

- candidate＝その手前にあり省略候補の交差点、target＝次に表示する交差点。順序を交換しない。
- center/branchesはWGS84の緯度経度、headingは北0で時計回りのラジアン。度数ではない。
- 3本以上の枝を持つ単一の実交差点。各枝は中心から外へ並ぶ折れ線。短い枝を消さず、複数の交差点を合体しない。
- 各枝は道沿いに最大28m、ただし次の次数3以上の交差点、端点、ループ等で止める。28m未満の枝もそのまま使う。
- heading＝実際のルート上の8m手前から中心へ向かう方位。CP/折り返し等の境界を越えない。相手アプリの隣接ノードによる方位と同一ではない。
- entryIndex/targetEntryIndexはbranches配列内の、実際に歩いて入ってくる枝のindex。枝をソートしたらindexも追従させる。最も下の枝を推測してはいけない。
- entryIndex省略時には実際のrouteInから復元を試みる。復元できなければ移植用runtimeは保持。学習時の旧欠損マスクと、実運用での保守的保持は区別する。
- routeOutや矢印・写真・看板はAI形状特徴量に使わない。現行モデルには「次のコマで曲がるか」を示す教師入力は含まれない。進入路と各枝の曲がり具合を追加した350特徴量である。

## 出力

`runtime/predict.py` は単一JSONまたは配列を受け、`decision: keep|omit`、`reason`、必要に応じて`keepScore`、`maxAngleDegrees`、`counts`を返す。

**omitはペア類似判定としての省略候補**であって、CPや曲がり角を削除する許可ではない。必須地点・道なり判定を通した後の比較にのみ使う。壊れた形状や進入路不明ならkeep。壊れたJSON/モデル等でプロセスが失敗したら、呼び出し側で該当コマを保持する。

スコアは重み付きRandomForestの葉のkeep比率を木全体で平均した値。校正済みの確率ではない。特徴量ベクトルはfloat32へ丸めてから、保存されたdouble閾値と `<=` 比較する。

## 350特徴量

正確な順序はsource/scripts/junction_experiment_features.pyの`vectors(row)['D']`を正とする。

- A：147次元。本数、8m/20mの24ビン循環角度ヒストグラム、ペア間の差。
- B：186次元。枝の一対一対応、最大角度差、対応差の統計、枝間角度、象限の差を追加。
- C/D：350次元。枝の長さと到達率、2/5/8/12/20mの曲がり、進入路と他枝との関係、対応枝の描画ずれ等を追加。
- DはCと同じ特徴量。保持クラス重み倍率とAI単体の閾値を学習側内側CVで選ぶ。

8m/20mへ届かない枝は端点で角度を測り、350特徴量では長さ・到達率も使う。短い道が自動的に「本数ゼロ」になる処理はない。左右反転はしない。

## 現行ルールの類似条件

本数が違えば非類似。同数なら、全枝の一対一対応が次を満たすか調べる。各枝の8m・20m両地点で、角度差20度以内、または角度差45度以内かつ `2×短い側の半径×sin(角度差/2)×2.6 <= 8`。2.6は元SVGの単位/m。2つの採取点で同じ枝の対応を維持する。データ不足時の保持は元実装と移植用入力検査を参照する。

AI追加保持案は、本数一致、8m/20m両方を満たす一対一対応の最大角度差30度以内、AI保持スコア0.2以上。元ルールで保持する場合はこれらに関係なく保持。**AI単体モデルのkeepThreshold（修正候補は0.5）と、この実験用ハイブリッドの0.2は別の設定。**
