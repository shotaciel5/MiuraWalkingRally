# 評価・回答修正・モデルの区別

評価者はP001の1名。①〜③が京都、④〜⑦が三浦。①〜⑦の700問から、ユーザーが不適切な地形として指定した3問を除外し697問。除外ID/形状キーはsource/config/junction-evaluation-exclusions.json。除外された元回答は削除せずrawに残す。

元ラベルはclear（明確に区別）/borderline（ギリギリ区別）を省略可能、indistinguishable（区別できない）を保持。uncertain、未回答、非ブラインドの回答は通常のprepareで除外。判断の優先順位は「残さなければコマ地図が破綻する地点を残す」。実際のイベントコースでの事故率等を測ったデータではない。

## 今回の修正

事例01＝三浦④の問題42、pairId `cbb5c4e3-75f2-40af-b7ca-c5ea65d647f8:pair:42` を、ユーザーがkeep→omitへ訂正。

「明確に区別」「ギリギリ区別」のどちらかは指定されていないので、二値ラベルだけ`omit`、choiceを`user-corrected-omit`として記録。borderlineの数を勝手に増やさない。元JSONを上書きしてブラインド回答のように見せることもしない。訂正は既存の判定結果を見た後のものとして扱う。修正記録はexperiments/corrected-recount/label-correction.json。

### 重要な区別

1. original-697の外側5分割は、当時の68keep/629omitで学習している。各ペアを1回だけテストし、同一ノードIDまたは端点12m以内が連結成分として同じ側に入る。テスト数140/140/139/139/139、学習数557/558。分割は地域で分けていない。
2. corrected-recountはこの予測値を固定した再集計。モデルは学び直していない。ハイブリッド条件も外側結果を見た後で探している。未知データへの性能保証はできない。
3. models/reference-original-697.jsonは全697問で学習した旧モデル。OOFの5個のモデルとは違う。
4. models/corrected-candidate/model.jsonは、最新の67keep/630omitで内側3分割選択→全697問学習した新候補。モデル重み選択は誤省略コスト5・不要保持コスト1、倍率1/2/4、閾値0.2/0.3/0.4/0.5。選ばれた設定は同じ場所のmanifest.jsonを参照。内側CVは設定選択用なので、そこにある成績を最終テスト精度と呼ばない。旧1.5%を新候補の実績に流用しない。
5. 移植用runtimeは、未知の進入路・壊れた形状を追加で保持する。その保守的例外を含めた受領先の成績も未測定。

## 次の評価

分割済みデータは再現検証に使える。条件や特徴量の選択は外側学習側の内側CVで行い、外側は触らない。ただし既存697問はすでに多数回の条件検討に用いているため、そこで測り直すだけでは最終独立評価にならない。

未使用の⑧はこの一式に含めていない。問題・回答・モデル予測にも触れていない。受領側が必要なら、入力互換性を検証し、モデル・切り出し条件・組み合わせ閾値を固定した後に別途評価者へ依頼する。移植先で描画前提を変えた場合は、新しい問題で人の評価を取り直す。

誤省略率だけなら全保持でゼロにできるので、不要保持率・残るコマ数・誤省略の実例も同時に比較する。
