## 1. P3-01：一覧・詳細から選ぶ

### 1.1 目的と今回の範囲

固定の開発用ラリー1件について、一覧 → 詳細 → 一覧をつなぐ。名称・概要・地点順・歩行距離と時間の概算・参加条件の確認状態を閲覧できるようにする。元のバックログ順序を維持し、P3-02の参加開始と保存、P3-03の参加中コマ表示、P3-04の到達判定、ゴール・特典は今回実装しない。

| パス | 責務 |
| --- | --- |
| / | 「三崎下町さんぽ」1件の一覧。概要・概算・未公開状態と詳細へのリンク。 |
| /rallies/misaki-shitamachi | 地点順・役割、概算、参加受付/達成方法/特典等の確認状態、一覧に戻るリンク。 |
| /poc | 既存の経路・全体地図・コマ・参照比較の確認画面。内容を保持して移動。 |

上部の参加者向け/運営者向けPoCの切替は画面へのリンク。認証・権限の分離ではなく、スポットの登録・編集・保存・公開はできない。対象AWS環境ではCognitoを使えないというユーザーの制約を保持し、ログインやAWSバックエンドを選定していない。

### 1.2 最小の設計とデータの対応

- 新しい汎用API・DB・動的ルートは用意せず、固定の詳細パス1本を静的ページとして実装。不明なラリーはNext.jsの404を返す。
- lib/demo-rally.tsが既存のcreateMisakiPocを使い、同じ固定経路の距離・歩行時間・地点名/順・階段の有無を取り出す。UI側で距離や時間の定数を別管理しない。
- 経路の1,026.6796486289682mを小数2桁の約1.03km、時速4kmの約15.4分を切り上げて約16分と表示。見学・休憩・信号待ちは含まず、坂/階段や速度で変わる概算と併記する。
- 地点列はS（三崎港周辺）→ C1（海南神社）→ W1（光念寺）→ C2（本瑞寺）→ G（三崎港周辺）。S/Gは同じ場所への別の訪問。W1は経由地候補、C1/C2はチェックポイント候補として区別する。
- 名称・紹介文は開発用コースの説明に限定。未確認の入口・通行・営業時間・費用・クーポン内容を事実として追加しない。「開発用・未公開」と「現在は参加できない」状態を一覧と詳細で示す。
- 既存の緑・生成りの色と書体を引き継ぎ、共通ヘッダー・概算・注意書きを小さなReactコンポーネントにまとめる。港のSVGは装飾であり、道路図・実際の経路・施設写真ではない。外部フォント/画像/地図タイルを追加しない。
- サーバーで生成できる閲覧ページとNext Linkで構成し、追加のクライアント状態、位置/カメラ権限、ブラウザ保存、個人情報の入力を導入しない。noindex/nofollowを継続する。

地点や道順は現地確認済みに格上げしない。生成/参照の差、現地の入口/通行/規制/安全性、実測精度と読解、参照10コマの図の保留はPoCの残課題のまま。

### 1.4 自己レビューと停止

要件U-01/U-02とP3-01の閲覧価値、概算と固定モデルの対応、経由地とチェックポイントの区別、未確認事項の明示、実際に使える往復リンクを確認した。参加者画面から参加や達成の記録は発生しない。既存PoCの配置変更による回帰を検証し、道路/補足データ・探索/分岐/投影アルゴリズム・依存の版は変更しない。新たな重要サービス選定やアーキテクチャ変更はなく、新規ADRは不要と判断した。

今回をfeature/rally-overviewでコミットしてレビューを求め、停止する。mainへのマージ・push・PR・公開・AWS利用は行わない。

次の提案はP3-02「参加を開始する」。ログインの有無、参加識別、保存範囲/保持期間、公開内容との対応をその着手時に具体化し、重要な判断は承認後に実装する。チェックポイント到達判定はP3-04の前に条件を確認する。今回はどちらも実行しない。
