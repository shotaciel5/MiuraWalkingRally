# P4-04b：短い枝のコマ表示方式の比較

- 日付：2026-11-09
- 状態：比較・検証済み。A/B案とも未採用で、人間の承認待ち。
- 対象：[固定データ照合](expanded-route-audit.md)で短い選択枝のため保留になった全45コマ。調査は次の着手指示で承認済み。
- 成果物：[A/B比較図HTML](reports/short-koma-comparison.html)、[比較数値JSON](reports/short-koma-comparison.json)。
- 基準：[AGENTS.md](../AGENTS.md)第0/3節、[ADR-003](decisions/003-koma-presentation.md)。向き・全枝・元角度/局所形状・次のコマまでの道路沿い距離は両案で維持する。
- 今回は方式比較のみ。実アプリ・歩行条件・経路/コマ生成の既定処理・保存を変更しない。

## 1. 比較の目的

現行の300×280の図は、30mを半径98の図上単位へ投影する。進入/退出の選択枝が30px未満なら黒点や矢印を区別しにくいため、図を保留する。今回の45コマでは選択枝の実長が約1.10〜8.88m。隣に分岐があるため追跡を止める場合もあり、道路不足やルート探索の失敗を意味しない。

分岐やコマを省略/統合したり、短い道路を長く描き直したりせずに、進む枝を読み取れる表現を比較する。実データと既存のアルゴリズムから図を作り、生成AIの画像を用いない。

## 2. A/B案

| 比較点 | A：30m参照図＋自動拡大図（推奨候補） | B：30m固定＋外側の進入/退出ラベル |
| --- | --- | --- |
| 道路と記号 | 全枝を同じ倍率で拡大し、道路上の黒点/矢印を保つ。 | 道路は30m固定。外側の「ここから入る」「こちらへ進む」と引出線で指す。 |
| 周辺情報 | 同じ倍率で建物・目印・階段も変換。見切れる周辺情報は30m参照図から確認する。 | 30mの周辺情報をそのまま保ちやすい。 |
| 短い枝 | 今回の45件すべてで既存の枝長条件を満たす拡大図を作れた。 | 指し先が中心近くに密集すると、どの枝か判別しにくい。 |
| 弱点 | 描画範囲が約3.01〜24.16mとなり、最大約9.98倍。目印が見切れる例と参照図を開く操作が増える。 | 記号が道路上から離れ、引出線が道路と混同されたり他の枝を指して見えたりする可能性がある。 |
| 追加確認 | 端末での図の実表示幅、記号/文字の重なり、拡大と参照の切替。 | 引出線の指し先、交差、ラベル配置、従来型コマとしての読みやすさ。 |

HTMLは同じ中心・進入基準・枝・距離のA/Bを横に並べ、小さい画面では縦に並べる。Aの参照図はdetailsから開ける。最短枝と近傍分岐、開始・終了・枝の条件が残る例を確認できる。参照図では短い枝に黒点/矢印を置かない。

目印の丸と名称は比較用の位置表示。採用実装で新しい目印表現へ置換する提案ではなく、既存の標識・施設記号を使う方針を保つ。枝端は隣の分岐・終端・表示範囲で止めており、その場で道路が終わることを表さない。

## 3. 数値と限界

| 対象 | A | B |
| --- | --- | --- |
| 現行の選択枝長30px条件 | 45/45件で通過 | 道路上の記号を外す案なので同じ条件では評価できない |
| 記号/指し先が他の枝に近い例 | 0/45 | 16/45 |
| 目印の位置が図の表示範囲内に残らない例 | 19/45 | 8/45 |
| 周辺の道路範囲 | 約3.01〜24.16m＋30m参照図 | 30m |

Aでは最短選択枝が図上36pxとなる範囲を計算し、既存のcreateKomaMapsへ渡した。36pxは現行条件30pxに余裕を付けた比較用の値。承認済みの製品仕様や地理的精度/安全性の閾値ではない。

近接指標は、進入点/退出矢印の先または引出線の指し先から、別の枝の線までの図上距離が12px未満の場合。これは目視すべき例を拾う比較指標で、読解の合否判定ではない。Aの0件は記号/文字の重なりや誤読がない保証ではない。

数値は300×280の図上単位であり、スマートフォンで縮小された実画面のpxではない。表示幅に応じた記号の大きさや、サムネイルでの可読性は採用実装で確認する必要がある。目印数もラベルの重なりを評価せず、位置が図の内側に残るかだけを数える。

45件は往復・再訪を含む延べ数。折返し・未知の幾何不足・別データの全ケースは網羅しない。枝の通行条件への注意が残る2コマは、拡大図にもその注意を保持している。表示可能でも通行確認済みにはならない。

## 4. 推奨する採用範囲（未承認）

A案を推奨候補とする。元の枝上の黒点と矢印を維持でき、Bより指し先の密集を減らせたため。最大拡大時に周辺の目印が全て見切れる実例があるので、30mの参照図を併用する条件とする。

次の実装タスクで承認を求める範囲は以下。

- 運営者の生成プレビューで、短い選択枝だけが理由の保留コマに、拡大図と30m参照図を用意する。拡大中であることを表示する。
- 元の角度・局所形状・全枝・進入基準、開始/終了/折返しの役割、コマ数・訪問順・次コマまでの道路沿い距離を維持する。分岐を追加/省略/統合せず、道路を延長しない。
- 建物・目印/標識・階段も道路と同じ倍率で扱い、見切れる情報は参照図へ残す。既存の目印記号を使う。
- 通常の描画可能なコマの表示を保ち、方向不明・欠落・不整合・拡大しても読めないものは引き続き保留する。徒歩の候補/保留/除外と現地未確認は維持する。
- 参加者側・固定PoCの表示変更、生成結果保存/公開、歩行ルールの緩和、AWSは対象に含めない。まず運営者画面で実表示幅と読解を確認する。

現行ADR-003は短い枝を保留する方針なので、この例外の採用は重要な表示判断として承認を得る。今回の比較や長さ条件の通過だけで採用済みとはしない。ADRの追加/改訂は採用承認時に行う。

## 5. 再現・検証・自己レビュー

~~~text
npm run koma:compare -- --check
npm run audit:expanded -- --check
npm test
~~~

koma:compareは固定データの45保留コマを再計算する。--checkは比較HTML/JSONとの一致確認、--writeはこの2ファイルだけの再生成。オプションなしはJSONを標準出力する。実DB・保存済み下書き/補正・元データを更新しない。外部通信・新しい依存・AWSは不要。生成資料の改行はLFに固定する。

## 6. 終了点

比較資料・検証・文書をコミットし、採用方式の確認を依頼して停止する。A案承認後の運営者プレビューへの適用は別タスクで実施する。
