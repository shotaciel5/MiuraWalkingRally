# P4-06d/e：保存済みコースの公開と参加者利用

- 日付：2026-11-10
- 状態：ユーザーがA「公開→開始→コマ閲覧まで」を明示承認。[ADR-018](decisions/018-published-participant-courses.md)として実装・検証済み。以下の案比較/メモリー確認はP4-06dの履歴で、承認後の実装は7節。
- 基準：[要件U-01〜05/A-05、6.3/6.5/7.1節](requirements.md)、[不変の保存済みコースADR-016](decisions/016-saved-course-snapshots.md)、[既存の公開境界](course-review.md#5-公開へ進む前に残る判断)。
- 目的：運営者のコースが参加者へ届き、固定デモ以外でも利用を始められるようにする。P4-06dでは仕様/開発順とメモリー上の成立性を確認し、承認後のP4-06eでアプリ/API/DBとブラウザを接続・検証した。

## 1. 最初の実装範囲Aと小さい代案B

**A案（推奨）：保存済みコースの参加者側への掲載→一覧→詳細→開始→そのコースのコマ地図を、一つのストーリーでつなぐ。**

1. 運営者が保存済み詳細で対象名/地点順/距離と確認事項を見て「参加者向けに公開」を選ぶ。
2. 対象と掲載先を確認して実行する。保存しただけでは一覧に出さない。既存の保存済みコースも、初期化や自動掲載をしない。
3. 参加者の一覧は掲載したコースだけを表示。詳細に地点順・チェックポイント/経由地の役割、道路上距離/歩行時間の概算を表示する。
4. 「このコースを始める」で開始を記録し、そのコースの全コマを通過順に閲覧する。複数の公開コースを利用でき、コース間で開始記録を混同しない。

B案は掲載→一覧/詳細だけを先に作り、開始/コマ閲覧は次へ分ける案。変更は小さいが、作成したコースを参加者として試す価値が後になる。Aの一連の価値を推奨する。

| 最初のA案へ含める | 後続 |
| --- | --- |
| 掲載するコースの明示選択、公開状態の永続保存、公開済みへのリンク | 掲載解除、公開後の差替/取下げ、確認結果の履歴 |
| 掲載コースの一覧/詳細、開始、コマ/地点の閲覧 | 可変コースでの達成/ゴール記録・QR/クーポン |
| 同じタブでの再読込後の開始状態、再開・保存失敗/版違い | 長期/端末間の進捗保存、ログイン/認可 |
| 現在の図・目印、近接分岐の拡大と30m参照図の再利用 | コマ地図の新方式や精度改善、近接コマの統合 |
| 同じローカルアプリの参加者画面への掲載 | AWS/インターネットへの配信・実地の一般参加受付 |

「公開」はまずアプリ内で参加者へ掲載する状態を指す。開発サーバーの接続先やネットワーク設定は変えず、AWSアカウント/外部デプロイを要求しない。現地の通行・入口・安全性を確認済みと扱わず、注意を保持する。将来の一般参加に必要な確認・認可/配信は独立して選ぶ。

## 2. 公開する版と参加者データのA案

保存済みコースのIDと内容指紋を、公開対象の版として固定する。運営者が後から下書きや台帳を編集しても、公開中や参加中の内容を黙って差し替えない。違う内容は別の保存済みコースを作り、別のコースとして明示掲載する。既存保存を上書きしないADR-016の方式を続ける。

開始記録は既存方針の匿名・個人情報入力なし・sessionStorageを使う。同じコース/版の再操作は元の参加ID/開始日時を使う。同じタブで再読込後も再開できるが、通常はタブを閉じると消える。現地到着や本人確認の証拠にはしない。既存の固定デモ記録を別の可変コースへ流用/自動置換しない。

開始だけならチェックポイント0件も扱う。開始/終了が同じ施設でも役割は分け、再訪するコマを別の通過として残す。今回ゴールを追加しないため、既存デモの「2地点達成でゴール」を可変コースへ勝手に適用しない。チェックポイント0件時を含む達成/ゴールの条件は後続の小タスクで確認する。

掲載解除/差替は最初の実装へ含めず、続くタスクで、一覧からの除外と開始済み利用者の扱いを確認してから追加する。掲載していないIDは参加者側で利用できない。保存済みの運営者向けURLを知っているだけで掲載済みとは扱わない。

## 3. 最小の画面と保存境界

| 画面 | 変えること |
| --- | --- |
| 運営者の保存済み詳細 | 未掲載/掲載済みと公開日時、明示掲載、参加者詳細へのリンク。再送で二重掲載にしない。 |
| 参加者の一覧 | 公開中の概要だけを読む。0件時に案内し、固定デモを自動で公開コースと扱わない。 |
| 参加者の詳細 | 保存時の名称/役割/説明・地点順・概算距離/時間、開始/再開。未登録写真を捏造しない。 |
| 参加者のコマ画面 | 前後/番号/訪問地点の選択、進入/退出・次までの距離、施設説明/目印と出典。運営者向けの全経路地図や編集操作をそのまま載せない。 |
| 固定デモ | 既存URLと開始/達成/ゴール/記録を保ち、検証用への明示リンクで開ける。参加者一覧の固定1件依存を解く。 |

近接分岐は運営者側で使っている拡大図と30m参照図を可変コースの参加画面へ再利用する案。表示幅不足/未知形状の保留は維持し、図形/ルート生成を変更しない。ADR-015は現在「運営者のみ」なので、Aの採用時に可変参加者への適用を明記する。既存固定デモの31コマはそのままにする。

保存済みモデルから、参加者用の必要な情報（コース版・地点/役割/説明・コマと補足情報）を作る。現在の台帳や生成器を参加者の閲覧で呼ばず、Graph/台帳全体・下書き編集条件・運営者の確認パネルをブラウザへ渡さない。

掲載情報は既存SQLiteの別表へ保存する最小案。現行v5から次のv6へ旧編集/削除・下書き/補正・保存済みコースを保持して移行する。保存済みモデル自身はv1を維持する。掲載日時・保存ID/指紋を持ち、同じ要求の再送では元の公開日時を返す。クライアントから計算結果全体や任意の公開日時を受け取らない。

UI/API/repositoryの境界を維持する。書込みは既存のローカルOrigin/JSON/no-store・小さい要求を使う。公開の確認/保存が失敗した場合に成功表示しない。破損/未対応記録や移行失敗を勝手に初期化しない。閲覧/参加開始で公開状態や保存済みモデルを書き換えない。新しい依存やクラウドSDKは不要。

認証は今回追加しない既存のハッカソン方針を維持する。画面切替を運営者の権限保護と扱わず、ローカルAPIの制約をそのまま本番セキュリティとしない。Cognitoを前提にしない。AWSの保存先/権限/費用と配信は利用可能化・明示承認後。

## 4. 採用時に確認した点（P4-06dの記録）

ユーザーはA案を明示承認した。初回の公開→一覧/詳細→開始/閲覧、保存ID/指紋による版固定と再送/タブ内参加記録、可変参加者への拡大/参照表示を採用する（ADR-018）。

これは現地の確認項目や一般向けの公開基準を確定する資料ではない。初回のアプリ内掲載から、実地イベントの受付やインターネット公開までを一度に承認したことにしない。QR/特典や掲載解除/公開後更新の方式も先取りしない。

## 5. 提案時の成立性確認と受入条件

固定6例で保存形式v1から参加者向けに必要な情報を投影し、JSON往復・全コマ/30m参照形状・地点との結合、元ペイロード非変更を確認した。既存の開始関数をメモリー上の保存先で使い、同じコースの再操作/別コース分離・CP0件の開始・固定デモ用のキー非変更も確認。DB接続・外部通信は行っていない。

| --- | --- | --- | --- | --- |
| 三崎周回 | 39 | 1 | 12 | 272,666 |
| 三崎→城ヶ島灯台 | 69 | 0 | 16 | 386,202 |
| 城ヶ島灯台→三崎 | 69 | 0 | 16 | 386,709 |

| うらり→海南神社→光念寺→本瑞寺→うらり | 41 | 2 | 11 | 279,783 |

CP/経由地は試算用に途中地点を交互に割り当てた。タイトル/説明・版情報やJSON項目に依存する値で、参加者用の実装型/容量上限を確定するものではない。コードはGit対象外の検証用で、アプリへ機能を追加していない。これを公開/API/ブラウザのテスト成功とは扱わない。

以下を初回実装の受入条件とする。

- 保存済み2種類以上を明示掲載し、参加者が一覧/詳細からそれぞれ開始して正しい全コマを開ける。
- 未掲載/不明/不正/破損を公開済みと表示しない。掲載成功の応答消失/再送、別要求・DB移行/失敗を検証する。
- 公開後の下書き/台帳変更で対象を差し替えず、参加者側の閲覧で台帳照合や再生成をしない。
- 開始の再操作/再読込/保存拒否、別コース/版・既存デモとの記録分離、0件/複数のチェックポイントを検証する。
- 41コマの海南神社#14や橋の往復、再訪・近接分岐の拡大/参照/保留、1280/390/320px、写真未登録・安全/出典の表示を確認する。
- 既存保存/運営者機能と固定デモの記録・31コマ/写真/ゴールを回帰確認する。

今回の仕様/開発順・メモリー確認をレビュー・コミットした後、採用確認を求める。公開API/DB移行・参加者可変画面の実装/検証は、承認後のP4-06eで行う。

## 7. 承認後の実装と受入結果（P4-06e）

2026-11-10の明示承認に基づきA案を実装した。運営者の保存済み詳細で確認・掲載し、参加者の一覧/詳細→開始→掲載版の全コマを閲覧できる。未掲載/不明IDは参加者に表示しない。公開ID/指紋/日時をSQLite v6へ保存し、台帳・下書き・道路を閲覧時に参照/再生成しない。保存形式v1・開始形式v3は維持する。

351件の単体、型検査/本番ビルド、固定道路/スポットと2種類の資料再現、開発/本番HTTP操作前後各34件に成功。Edgeで6コースの全227コマ、CP0件/複数・再訪と橋往復・海南神社#14、拡大/30m参照とレイヤー、1280/390/320pxを確認した。公開応答消失/再送・DBロック/並行公開・移行、コース/版ごとの開始・再読込・保存拒否/読戻し失敗、不正/破損の保持と失敗表示、旧固定デモも回帰確認した。詳細は[運営画面20節](operator-app.md#p4-06e)と[参加者画面8節](participant-app.md#published-participant-flow)。

受入範囲を自己レビューし、掲載解除/更新・可変の達成/ゴール、QR/特典・AWSを追加していない。現地確認/実機スマートフォン・一般参加受付/配信は未実施。今回のコミット後にレビューを求めて停止する。

## 8. 用語と次の公開切替仕様（P4-06f-1）

以前の「可変コース」は、運営者がスポット/経由地を選んで生成したコースを指す。今後は「作成したコース」「公開したコース」と呼び、公開版を固定するADR-016/018を維持する。参加中に道順が変わる機能や別のコース種別は追加しない。

次は[公開・非公開切替の仕様案](course-publication-lifecycle.md)。公開停止/同じ版の再公開を最小範囲として、開始済みも次回読込から停止するAと、開始済みだけ継続するBを比較した。採用は未決定で、P4-06eのアプリ/API/DBは今回変更していない。1〜7節はP4-06d/e時点の記録として保持する。

## 9. 公開停止/再公開の適用（P4-06f-2）

8節のA案をユーザーが明示承認し、[ADR-019](decisions/019-course-publication-controls.md)で公開停止/同じ内容の再公開を実装した。停止すると開始済みも次回読込から閲覧を止め、タブ内記録は保持する。同じ保存版を再公開した後は元の参加ID/開始日時を引き継ぐ。状態の変更版とコース内容の版を分け、内容の差替や記録移行は行わない。

現在の保存はSQLite v7。公開状態の再送/競合/移行と、参加者の最新状態確認/停止案内を[運営画面22節](operator-app.md#publication-controls)で検証した。8節は採用前の比較記録として保持する。

## 10. 写真ラリーへの参加者表示の変更（P3-09）

[要件v0.3](requirements.md)と[ADR-020](decisions/020-photo-walk-participant.md)でQR/AI認証・クーポンを撤回した。一覧カードから直接開始し、独立詳細はコマへリダイレクトする。先のCP名を事前表示せず、該当コマで撮影とゴールでの写真提示を案内する。運営者の元データ/図形/距離・公開停止/同じ版の再公開・開始記録は保持する。

この節を現在の参加者の導線/表示とし、1〜9節の詳細/地点一覧や距離等は当時の仕様記録として保持する。画像/訪問の認証、撮影枚数や終了の自動認定は行わない。[参加者画面11節](participant-app.md#photo-walk)を参照。
