# 運営者のタスク導線改善（P4-10）

ユーザーの要望により、初めて触る人が「コースをつくって公開する」という仕事を追えるように、入口・次操作・詳細表示・空状態を整理する。初見の人に使いやすくなったかは、実ユーザーのテストが必要であり、今回の実装だけで理解度改善を実証した扱いにはしない。

## 画面と操作

- 作業ホーム：主操作をコースづくりにする。既存の保存済み下書きを読み取り、あればその名前と再開リンクを表示する。スポットの追加・編集は、使いたい場所が足りない場合の補助作業にする。保存状態の読込エラーと初回の未作成を区別する。
- 全体の案内：「1 地点を選ぶ → 2 コマを確認・保存 → 3 参加者へ公開」。既存のURLは維持し、作業ホームとスポット管理も開ける。作成画面でステップ2を押すと保存/生成の操作欄へ移り、未保存のまま古い生成結果へ進めない。
- 地点選択：不足しているスタート/ゴール/コース名と保存状態を表示する。選択した場所の役割ボタンを示し、チェックポイントと経由地の違いを直前に説明する。道路情報は詳細表示へまとめるが、候補計算/地図更新のためSpotConnectionのマウントは維持する。
- 保存と生成：未保存なら地点の保存が主操作。保存後はルート/コマの生成が主操作になる。保存してから生成する既存の2操作と、無効条件/競合/補正の再確認条件を維持する。台帳更新や未保存破棄は管理用detailsへまとめ、競合/地点変更/補正の問題があるときは開いて復旧を案内する。
- 生成結果：まずコマへ移れる案内を示し、選択コマ→保存→全体図→訪問順/道路候補→確認箇所の順に読む。版情報・補正・再生成はdetailsへ。保存ボタンは公開設定へ進むことを説明し、保存だけで公開されないと明示する。
- 保存済み一覧：コースを開いて確認/公開できると伝える。0件なら作成開始ボタン、読込失敗なら再試行を出す。公開済み・未公開・停止中の状態に応じて、参加者画面の確認か公開操作を主にする。

## 維持する条件

API・DBスキーマ・1件の作業下書き・保存版の固定・匿名参加・公開確認/停止/再公開の動作を変更しない。ロール管理、認証、クーポン、QR、強制チュートリアルや利用計測は追加しない。ルート/コマ/AI省略/写真の処理と外部取得の条件はそのまま。ホーム/参加者側の表示も対象外。

作業ホームは既存のリポジトリから下書きを読み取るNode.js動的ページにした。新しい保存先や集計APIは追加しない。ページ表示のために作成中の入力を自動で上書き/初期化しない。
