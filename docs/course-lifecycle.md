# 保存済みコース・下書き・歩行時間（P4-11）

2026-11-14。ユーザーの依頼3点と、削除方式B「公開停止と削除を一度に行う」の明示承認を反映する。[ADR-028](decisions/028-course-lifecycle-and-walking-time.md)。

## 操作と結果

- 保存済み詳細の末尾で「コースを削除…」を押し、対象名と影響を確認する。取消では変更しない。公開中なら「公開停止して削除する」で一度に確定する。
- コース一覧・詳細と参加者一覧から外し、開始済みの参加者も次回読込みから開けない。すでに開いているコマの強制終了やブラウザ保存済み開始記録の遠隔消去は行わない。
- コース保存成功後は、作成中の名称・開始・終了・途中地点と、その下書きの手動到達点補正を空にする。保存済み版の入力・ルート・コマ・目印は保持する。次は新しいコースを作成できる。
- 保存失敗時は下書きを残す。古い画面から保存を再試行しても、後から作った下書きは消さない。
- 運営者の生成/保存済み表示と参加者の目安は時速3kmで計算し、分単位の表示は切り上げる。3kmなら60分。見学・休憩・撮影・信号待ち・坂道や階段の減速は含まない。

## 保存境界と整合性

SQLiteをv7からv8へ移行し、course_deletionsとworking_draft_stateを追加する。既存コース・公開情報・下書き・補正・スポットの行は移行時に書き換えない。新規DBと旧版からの既存マイグレーションもv8へ到達する。保存版payload v1/v2/v3は変更しない。アプリから開く際に自動移行する。操作テストは専用DBを使う。実DBの最終照合については以下に記す。

削除は1つのトランザクションで対象の指紋と公開状態の版を確認し、コースID・指紋・名称・削除日時・削除時の公開版を記録して、公開情報と保存済みpayloadを削除する。古い公開状態なら409で中止する。途中失敗は全体を戻す。同じ削除要求の再試行は同じ削除記録を返す。削除したIDは再公開できず、同じ内容の再作成は別IDとして保存できる。復元画面と削除済み一覧は設けない。スポット・共有写真・別コース・別の作業下書きは削除しない。

コース保存と一致する下書き/補正の初期化も1トランザクションで処理する。保存前に台帳・下書き・補正・目印採否が変わった場合は保存を中止する。保存の重複要求では既存版の識別を検証し、現在の下書きが保存入力に完全一致する場合だけ初期化する。下書きが空でも最後の版番号を保持し、次の下書きで版を使い回さない。手動補正を空にするときも版を進め、古い画面の補正要求を受け付けない。

DELETE APIは既存と同じローカル同一オリジン・JSON・サイズ制限を使い、Cache-Control: no-storeを返す。これはローカル用の境界であり、公開運用の権限保証やAWSバックエンドの選定ではない。

## 既存版と初期登録

既存版のルート・コマ・指紋・保存時の歩行速度は変更しない。表示時だけ総距離から時速3kmの概算を計算する。新規生成の標準速度は3km。同梱コースは既存ID/指紋を保つため、登録用payload生成に限り従来の4kmを明示する。通常画面ではその同梱版も3kmの目安を表示する。

demo:seedを再実行しても、削除した固定IDやコース保存で空にした下書きを復活させない。画像・道路・スポット・省略モデル・ホームの選定コマを変更せず、外部API・依存・環境変数も追加しない。
