# ルート上の目印取得と運営者の採用判断PoC（P2-09）

2026-11-12。ユーザーが、ルート決定後に該当交差点だけ取得する流れと、全候補を選択可能にし「一時停止・横断歩道は初期採用、信号・固有物等は初期不採用」とする方針を承認。トークンを設定し、一回のPoCで実装/検証を進めるよう明示依頼した。[ADR-021](decisions/021-route-landmark-review-poc.md)に範囲を記録する。前回の[キー不要PoC](visual-landmarks-poc.md)は比較資料として保持する。

2026-11-12更新：[P2-10](landmark-preparation-poc.md)で階段の必須表示、写真候補の自動準備/一覧、GUI/CLIの共通処理を追加した。地点取得は20件ずつ再開でき、地点キャッシュ上限は200件。品質不足の結果も24時間再利用する。以下のP2-09検証記録は前段の成果として保持する。

## 操作と今回の成立範囲

1. スポット/順序を選んで下書きを保存し、通常のルート・道路のコマを生成する。この段階でMapillaryを呼ばない。
2. 生成プレビューの「このルートの目印を選ぶ（PoC）」から **/operator/landmarks/review?source=draft** へ進む。固定例は **/operator/landmarks/review**。
3. OSM候補を先に表示する。トークン設定時は、このルートの未取得交差点について非同期に地物を準備する。進捗/停止/再試行を表示し、既存キャッシュは再取得しない。
4. コマのチェックボックスで採用/不採用を変える。図の表示中の記号を押しても切替可能。不採用の候補も図に出す表示を選べる。
5. Mapillary候補の「写真と検出領域を確認」で、その地物に対応する検出と画像を少数取得する。元写真・検出領域・自動切り出しを確認できる。写真/信号等は運営者が採用した場合だけ図へ出す。
6. 「採用状態を保存」でPoC専用のルート別記録へ保存する。再読込み・ローカルサーバー再起動後も復元し、同時編集は競合として扱う。

**通常の保存済みコース/公開版/参加者表示への反映はまだ行わない。** 今回は実取得→切り出し→運営判断→PoC保存を一通り検証する。参加者への適用には、画像の参照/出典も含めた保存版との統合を別途行う。SQLite v7、既存の生成/保存/公開/参加記録は維持する。採用は現地確認・安全確認・公開承認を意味しない。

## 初期採用と根拠

| 候補 | 初期値 | 表現 |
| --- | --- | --- |
| 明示された止まれ標識 | 採用 | 標識記号。分類/出典・推定位置を表示 |
| OSMの一時停止点 | 採用 | 「一時停止点（標識未確認）」と明示。既存の破線の停止点記号を使用し、標識の現物を補作しない |
| OSMの横断箇所 | 採用 | 「形態未確認」と明示。横断箇所の記録からゼブラ塗装や標識の現物を推測しない |
| Mapillaryの横断歩道の路面表示 | 採用 | 検出分類に基づく候補。位置/見え方は現地未確認 |
| 信号・バス停・店舗看板/広告看板/バナー | 不採用 | 運営者が個別に採用可能 |

すべての候補を運営者が切り替えられる。採用数の1〜3個という旧PoCの上限は使わない。すべての採用候補を配置対象にし、道路/他記号を隠すため配置できない場合は「配置待ち」と数を明示する。黙って採用解除や道路形状の補作をしない。

OSMは固定データ内の全該当候補から30m内を抽出し、既存コマの最大4候補という表示制限を経由しない。施設名・建物形状は新画面の図に表示しない。同種でも別出典を自動統合せず、OSM/Mapillaryの重複の可能性を運営者が確認する。停止/横断の候補を漏れなく採用するのは「得られた候補」の範囲で、実際の道路上のすべての標識/横断歩道を検出したという保証ではない。

## 取得と画像処理

- 外部SDK/モデル/依存は追加せず、NodeのfetchでMapillary Graph APIを読む。Mapillary自身の既存の物体検出を利用する。画像生成AI・独自OCR/物体認識モデルは使わない。
- 交差点は中心座標を使って再訪をまとめ、約32mの範囲を取得し、各コマは30m内を表示。ルート外の座標/任意URLをクライアントから指定できない。
- map_featuresの対象物の推定座標を使用する。カメラGPSを対象物座標として流用しない。採用状態はルート/コマ/候補ごとで、同じ場所でも別の進入コマの判断を独立して保持する。
- 対象分類はstop、crosswalk、traffic-light、店舗/広告看板・banner。未知分類を勝手に現物記号へ変換しない。
- 地物のdetectionsから対応画像と領域を取得し、MVT 2.xのポリゴンを復号。画像座標の上下を変えず矩形範囲を求め、ブラウザCanvasで縦横比を保って64pxへ切り出す。図はその画像を小さく表示する。生成AIによる補完や背景除去は行わない。
- 切り出し元で20×12px未満、縦横比が1:4〜4:1を外れる領域等は画像候補から除外する。これは仮の品質条件で、識別性の保証ではない。画像処理版2を記録し、旧条件の結果を再利用しない。
- 保存するのは限定したサムネイル/検出範囲・撮影者/撮影日・出典ID。切り出しPNGは表示時にブラウザ内で作る。再閲覧で外部API/認識を実行しない。

初回の各交差点リクエストはクライアントから順に実行する。一時停止後も実行中の1地点は完了し得る。新しい永続ジョブ基盤は設けない。P2-10以降は20地点ずつ未取得地点から再開できる。地物は100件×最大2ページ/地点、検出応答もサイズ制限し、写真候補はP2-10以降、最大8地物から画像のある3候補を目標に自動準備する。上限や取得失敗を「対象なし」と同一視しない。

## 保存・秘密情報・失敗時

| 項目 | 実装 |
| --- | --- |
| 保存先 | .local-data/landmark-poc。LANDMARK_POC_DIRで変更可能。DB本体と独立したJSON/画像ファイルで、Git対象外 |
| 再利用期間 | 7日。過ぎた結果は再取得対象。7日で物理削除する機能ではなく、期限切れファイルも保存上限へ数える |
| 件数 | P2-10以降、地点200、写真20、採用状態50ルート、品質不足100件まで。既存記録を自動削除せず、上限時は失敗を表示。必要なら別のPoC保存先へ切り替える |
| 大きさ | Graph応答2MB、画像1.5MB/件。公開画像の全域/原寸一括取得はしない |
| 一貫性 | 同一プロセスの進行中取得を共有。採用保存はロック/一時ファイル/置換と期待revisionで競合を検出。破損時に初期化・成功扱いしない |
| ルート変更 | 入力から再生成したルート/OSM候補の指紋をサーバーで再確認。古い画面からの保存/取得は409 |
| 認証情報 | MAPILLARY_ACCESS_TOKENは.env.localのサーバー専用変数。Client secretは使わない。ヘッダ認証で送信し、URL/ブラウザ/ログ/キャッシュにトークンを含めない |
| 画像取得 | APIから得たHTTPSの許可CDNだけ。CDNへトークンを送らず、リダイレクト/過大応答/非画像を拒否。署名付き配信URLをブラウザや保存メタデータへ渡さない |
| ローカルAPI | 既存の同一Origin/JSON/サイズ制限、no-storeを使用。ルート/候補をサーバーで照合し、任意パス/任意URLを受けない |
| 失敗 | 設定/認可/通信/制限の失敗、候補なし、写真品質不足、保存失敗/競合を分ける。OSM/取得済みの図は継続し、操作途中の採否を保持する |

認証による運営権限制限は既存アプリ同様にない。ローカル研究用のPoCで、AWS移行や一般公開用のジョブ基盤/画像配信/認可を採用したものではない。

## 利用条件の確認（2026-11-12）

- [公式SDKのAPIフィールド](https://github.com/mapillary/mapillary-python-sdk/blob/main/src/mapillary/config/api/entities.py)で、地物/画像/検出領域の関係を確認し、実API応答で検証した。[MVT仕様](https://github.com/mapbox/vector-tile-spec/blob/master/2.1/vector_tile.proto)に従いポリゴンだけを限定的に読む。
- [画像の公式ライセンス説明](https://help.mapillary.com/hc/en-us/articles/115001770409-CC-BY-SA-license-for-open-data)のリンク先は[CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/)。画面に作者/元画像/Mapillary/ライセンスと切り出し・縮小の改変を表示する。コードのライセンスと画像のライセンスを混同しない。
- [派生メタデータの公式説明](https://help.mapillary.com/hc/en-us/articles/115001777705-OpenStreetMap-compatibility)には別公開時の公開/ODbL条件がある。今回は素材/メタデータをGitや外部サーバーへ配布しない。公開版への統合時にはデータ提供条件を再確認する。
- [詳細API文書](https://www.mapillary.com/developer/api-documentation/)と[規約](https://www.mapillary.com/terms)はこの調査環境ではログイン画面のまま。認証付きAPIが動くことは、無期限保管/大量取得/一般配信を包括承認する根拠にはしない。今回の小範囲・有限のローカルPoCから拡大する条件は残る。

## 実データの結果

三崎下町の固定31コマが通る16地点に限定して取得できた。分類条件に合った異なる地物IDは43件。コマごとの30m内の候補としては再訪を含む138行になる。

| 出典 | 結果 |
| --- | --- |
| Mapillary | 横断歩道の路面表示3件、信号2件、店舗/広告看板/バナー38件。止まれ標識は今回0件 |
| OSM | 一時停止点2件、横断箇所4件、信号1件、バス停2件。明示された止まれ標識は今回0件 |
| 実写真 | 店舗看板5候補を試し、3件で品質条件に合う切り出しを保存。2候補は小さすぎる/細長い等の条件で画像候補なし |

出典ごとの件数であり、別出典の同じ実物を統合した地点数ではない。標識0件/画像なしを現物の不在とは判断しない。写真に古い撮影も含まれ、対象方向/季節/遮蔽/現物の更新を未検証。固有の店名を自動で特定したり、正確なブランド認識ができたという成果ではない。

## 残る判断

現地での識別性/向き・重複/位置を数地点で確認すること、運営者が撮影方向/別画像・配置を直す範囲、保存/公開版と画像出典を固定する方法、Mapillary更新/失効時の再確認と保持条件。今回の初期採用はPoCに適用し、通常参加者への採用はこの確認後に行う。今回のコミット後に停止し、これらは提案にとどめる。
