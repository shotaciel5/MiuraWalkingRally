# ③ ルール＋機械学習の追加保持（P4-08a）

2026-11-13。ユーザーの「資料が候補としているのが③なら、このアプリでも③を用いてほしい」という明示指示で実装。P4-08のルール単独版を置き換える新規生成の標準設定とする。[ADR-026](decisions/026-hybrid-koma-omission.md)。

## 採用した処理

資料の corrected-candidate/model.json（350特徴・200本のRandomForest、float32入力）を再学習せず同梱する。ルールが残したコマはAIで削除しない。ルールが省略できるとした候補と、その後の表示対象の比較だけに学習済みモデルを使う。枝数が同じ・最大対応角度差30度以下・保持スコア0.2以上なら追加で残す。この値は保持判断のスコアであり、現地で迷う確率や精度保証ではない。

現在の表示対象までの区間を確認し、追加保持したら比較対象を更新して再走査する、資料どおりの反復復帰を維持する。直進信号だけの中間コマは比較の境界にせず、手動編集やCP等で保護された場合は境界になる。

元の開始/終了・CP/経由地・折り返し・右左折・確認待ち・手動編集の保護は継続する。形状不足・進入枝不明・モデル不正/推論失敗は省略の根拠にせず保持する。運営者には失敗がある場合のみ案内し、道路や目印の図形を補完しない。

## 実装と交換境界

- lib/route/omission/features.ts：受領Pythonの350特徴をTypeScriptへ移植。枝対応の同点処理も合わせ、特徴量にID・正解ラベル・評価情報を使わない。
- assignment.ts：SciPy v1.16.0の矩形割当の最短増加路方式を移植。BSDライセンスと出典をSCIPY-LICENSE.txtへ保存。
- model.ts / inference.ts：モデルの構造・同一性検証、float32化後の木の比較、学習済みモデルの推論と③の条件判定。モデルはサーバーで一度読み、不変にする。
- analyze.ts：従来の形状/保護を先に評価し、ペアごとの判定を固定する。selection.tsは固定済み判定を使う純粋処理で、ブラウザへモデルを送らない。

推論はNode.js内で完了し、Python・scikit-learn・外部API・AWSサービス・追加npm依存を実行環境へ要求しない。Mapillary等の新しい外部取得もない。Amplifyでの配布サイズ/実行時間・DBの移行は別途実環境で検証する。

## 版とUI

新規プレビューの標準は「道なりを省略（標準・AI補助）」。通常画面には結果と設定を開くボタンだけを置き、ダイアログ内で「ルールのみで比較」「全交差点」へ切り替える。目印を編集した元のコマの保護・元番号との対応は従来どおり。保存時の検証票も3方式を区別する。

保存payloadはv3のまま、省略planだけをv2へ追加する。モデル原本SHA-256、特徴量版、閾値・角度条件と、各ペアのスコア/角度/枝数/判定理由を保存する。必要な全比較が揃うことを検査し、表示対象を再計算して照合する。モデル差替や現在の道路変更で保存版を再推論しない。

既存v1/v2コースと、以前のv3・省略plan v1をそのまま読む。旧ルール版にはAI切替を出さず、保存した表示を保持する。AI補助版にするには再生成・別保存が必要。保存済みの切替は確認用で、公開した参加者の版を変更しない。SQLite v7を継続し、スキーマ変更はない。

## 独立した照合

通常のnpm testに境界/異常/保存互換を加える。受領資料とは独立した実装の一致検証は次で実行する（Python環境にnumpy/scipy/scikit-learnが必要。通常起動には不要）。

```powershell
npm run omission:verify -- --python C:/Python312/python.exe
```

このコマンドは資料の凍結したPython特徴量・元のCJS運用判定・現モデルと旧OOFモデルをオラクルとして読み、外部通信/再学習/元資料の書換えを行わない。

## 実データと確認状況

道路/スポットを変えず、三崎さんぽは全39→ルール33→③33、城ヶ島は全29→ルール28→③28。③の推論対象はそれぞれ109/21ペアで、追加保持判定は2/0ペア、失敗は0。追加保持判定の相手が最終表示対象になるとは限らないため、最終枚数が同じでもモデルを使っていないという意味ではない。枚数を減らすための閾値調整は行わない。
