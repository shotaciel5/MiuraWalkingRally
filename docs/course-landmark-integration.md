# コースの目印・切り抜き写真の運営画面統合（P4-07）

ユーザーの「PoCが終わったら運営者システムの選択中のコマへ統合」に基づく実装。地域事前取得PoCと画像なし候補の除外は完了済み。新しいAPI取得・認識モデル・依存は追加しない。

## 操作

1. スポット・訪問順を下書きへ保存し、通常の `/operator/preview` を開く。
2. 「選択中のコマ」枠内の「このコマの目印」で交通記号・128×128の切り抜きを選ぶ。変更は図と一覧へ即時反映する。一時停止/横断箇所は初期採用、写真/信号/バス等は初期不採用。階段は道路属性から常時表示する。建物形状・道路/施設の名称を図へ出さない。
3. 「目印の採用を保存」で作業状態を保存する。未保存の採否がある間はコース保存を無効にし、ページ離脱を警告する。「このコマを初期状態へ」はそのコマだけを戻す。再訪はコマごとに採否を選べる。
4. 上の「この結果を保存」で新しい保存版を作る。保存済み詳細の同じ枠は読取専用。既存の確認・公開操作で参加者へ渡す。

採用状態はそのルートの指紋で保存し、コース保存時に改めてサーバーで検証する。採用の保存は全コマの編集をまとめて保存する。エラー時は選択を残す。同時操作・下書き/補正/台帳変更は最新内容の再確認を要求する。PoC専用URLは比較/互換のため残すが通常プレビューから別画面へ移る必要はない。

## 保存と表示

- SQLiteスキーマv7は維持。保存payload v2にコマごとの採用地物と、採用写真だけの作者/画像ID/撮影日/切り出し領域/ハッシュ/静的パス、地域索引のID/内容ハッシュを固定する。クライアントから全生成モデルを受け付けず、小さなreceiptを照合する既存方式を継続する。
- 旧payload v1はそのまま再表示し、現在の初期採用を後付けしない。同梱デモの既存ID/指紋も保持する。新規作成からv2を使い、既存コースへ写真を追加する場合は下書きから再生成・採用・別保存する。
- v2は保存内容に含まれる地物/写真だけを、同じ共有描画で運営者/参加者へ表示する。元の角度・全枝・進行方向を変えない。拡大図は目印座標も同倍率、見切れは30m参照図を使う。道路や他の記号に置けない目印は採用を保持し、運営側に配置不可を案内する。
- 公開コースは地域索引や採用作業状態を再参照しない。採否変更後も同じ保存版の表示・再送を維持する。同じ表示内容の再送は重複登録しない。
- 128px画像は内容ハッシュ付きの同梱ファイルを参照し、DBに画像バイト列を複製しない。地域バッチは古いハッシュのファイルを自動削除しない。配布更新時も保存済みコースが参照する画像を保つ必要がある。
- 採用した写真の作者/元画像/CC BY-SA 4.0・加工/撮影日を運営画面と参加者の折りたたみ出典に表示する。追加地物はMapillary/ODbL、道路/記号はOSM/ODbLを表示する。参加者のCP名の表示条件・撮影案内・距離非表示・タブ内開始記録は維持する。

## 境界と制限

Mapillary通信は行わず、トークンがあってもWeb取得を拒否する。写真がない固有物は候補に出さない。候補/写真がない地点も道路だけで生成を続ける。OSM背景タイルは従来の外部通信のまま。

写真の対象物位置/古さ/進入方向からの見え方や道路通行は現地未確認。配置できることは視認できる保証ではない。保存済み画像の撤去/権利失効時の対応、作業用採用記録の上限、全組合せの実機確認は後続。AWSのDB/ストレージ/配信・認証を選定/操作しない。静的素材と保存境界の分離は継続し、AWS動作保証とはしない。

## 検証・レビュー

単体テスト・型検査・ビルド、隔離DBと開発/本番ブラウザによる採用→保存→公開→参加者表示、旧v1の表示・道路形状の回帰を確認する。最終結果は以下へ記録する。実DB・秘密情報・元道路/地域素材を変更せず、作業ブランチへコミット後に停止する。

### 自己レビューと停止

通常プレビュー/保存済み/参加者の共有表示とv1/v2境界を照合した。採否/画像/出典を新しい保存版に固定し、元のルート探索・枝・進入基準を変更しない。写真がない固有物の除外・初期採否・階段必須・Web外部取得禁止を維持し、PoCの取得機能を復活させない。古いコースへ新しい初期採用を混入させず、後の再選択や再送で公開版を変えない。

作業ブランチfeature/integrate-course-landmarksでコミットし、ユーザーレビュー待ちで停止する。次は評価者向けコースの目印選定、スマホ実機/現地での読解と見え方の確認を提案する。mainへマージ・push・実DBへのデモ投入・AWS操作は行わない。
