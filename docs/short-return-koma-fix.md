# P4-04d：海南神社の短い折返しコマの表示修正

- 日付：2026-11-09〜10（JST）
- 状態：ユーザーから「三崎町さんぽの海南神社14番が確認待ち」と報告。再現・修正・検証済み。

## 1. 再現と到達点の違い

利用中の下書き/保存済みモデルを読取専用で確認した。うらり→海南神社→光念寺→本瑞寺→うらりの41コマ、道路上距離約1,287.390m。問題は次の並びで再現する。

| コマ | 保存モデルの位置と動作 | 次まで |
| --- | --- | --- |
| #13 | node/2845402200の交差点から海南神社の道路上候補へ進む | 約8.406m |
| #14 | 道路の途中の自動候補点（仮ID -1）で海南神社に対応し、来た道を折り返す | 約8.406m |
| #15 | #13と同じ交差点を再訪し、次の地点へ進む | 約37.470m |

#14は元OSMに新しい交差点が増えたという記録ではなく、施設へ対応付けた道路上の途中の停止/折返点。旧固定PoCでは海南神社の仮到達点をnode/2845402200にしていた。現在の自動候補はその交差点から約8.4m先にあり、行って戻るコマが必要になる。施設代表位置・道路上候補は実際の入口確認とは別である。

ユーザーが以前見た画面と完全に同条件の保存記録はないため、過去の全コマ差を断定しない。直近の表示改善後のコミットでは、道路固定データ・到達点計算・経路/分岐抽出に変更がないことも確認した。コマ数を減らす、到達点を元の交差点へ戻す、近接コマをまとめる判断は今回含めない。

## 2. 直接の表示不具合

#14の元形状・方向・全枝は存在し、短い枝の参照形状も保存されていた。旧拡大処理は、選択枝を画面上約36pxにする倍率だけを計算していた。同じ枝で折り返す場合、黒点は枝端、矢印端は点列の76%の位置を使うため、直線に近い枝では中心間隔が約8.64pxになる。既存の14pxの条件を満たせず、拡大しても保留になった。

5代表コースの45対象ではこの短い折返しを網羅できていなかった。今回の41コマ経路を回帰入力へ追加し、修正前に「300pxで表示できない」という失敗を再現してから修正した。

## 3. 修正と維持する条件

同じ枝が進入/退出の両方の場合、元の黒点/矢印端の実距離から16pxの間隔を目指す倍率も計算し、従来の枝長を満たす倍率との大きい方を使う。元点列・全枝・建物/目印/階段を同倍率で変換し、既存の方法で前方の点列を切り出す。記号を道路の外へずらしたり、架空の道路を足したりしない。

切出し後も実際の枝長30px・別枝まで12px・記号間14pxの条件と、表示幅160〜300px・方向/形状の条件を再確認する。間隔は既存の判定どおり黒点中心と矢印配置点で測る。これらの基準は緩和しない。幅が足りない場合や記号が実際に重なる場合は保留を続ける。30m参照図と注意表示も維持する。

保存済みの元モデルは不変で、表示時の計算だけを修正する。既存の保存済みコースは再生成/上書きせずに表示へ反映できる。ルートの41コマ・距離/順序・到達点、保存形式v1/SQLite v5、参加者固定コースは保持する。拡大倍率の実装上の不足を既存の表示条件に沿って修正したもので、新しい通行/公開方針は採用しない。
