# 運営者ダッシュボードと地図の見やすさ（P4-12）

2026-11-15。ユーザーの依頼に基づき、運営者の作業を画面内のパネルへ整理する。コース生成・保存・公開の条件は維持する。

## 画面の使い方

- 作業ホーム：登録スポット数・保存コース数・下書きの有無を表示し、作成の再開と最近の保存コースを開ける。
- 地点選択：左に候補の検索/一覧、中央に地図、右に選択地点と訪問順を置く。右の入力欄と候補一覧はパネル内でスクロールし、保存/生成の主操作は下端へ固定する。
- スポット台帳：候補/検索・地図・詳細/編集を横に配置する。追加/編集/削除や道路との接続確認は従来の処理を使う。
- 生成・保存済みの確認：選択中コマ・全体地図・編集パネルを同時に表示する。右の「目印」「コマ一覧」「コース/公開・設定」で補助作業を切り替える。保存ボタンはタブを変えても画面上部から使える。
- 保存済みの公開/停止/再公開/削除は「公開・コース設定を開く」から操作する。保存済みを開くと「公開・設定」を初期表示し、保存直後も公開操作へ進める。保存済みのコマ・目印は読取専用のまま。

幅1100px以上・高さ650px以上では、ページを表示領域に収めて各パネルをスクロールさせる。1366×768等のPCを主な作業環境とし、狭い画面/低い画面は縦配置とページスクロールで操作できるようにする。すべての機能を同時に開くことや、小画面へ無理に縮小することはしない。

## スポットの絵アイコンと名称

文字の丸アイコンを、カテゴリごとの線画SVGへ変更する。飲食・市場・カフェ・買物・景観・歴史/宗教施設等の意味を表し、色と既存のカテゴリ名を併用する。アイコンは同梱のパスで描き、画像サービスや新しい依存を追加しない。

表示中の個別スポットには、ホバーなしで名称を表示する。密集した場所は既存のクラスタを使い、件数のまとまりを拡大すると個別の絵と名称が現れる。長い名称は表示幅を制限し、選択詳細とアクセシブル名には全文を残す。名称はDOMのtextContentへ設定し、入力をHTMLへ連結しない。

絞込み・地図/一覧からの選択・位置指定・背景地図の再試行を維持する。背景タイルは従来のOpenStreetMapで、外部通信や利用条件を新しく変更しない。

## コマと全体地図の連動

地図のコマ番号、重要地点、右の一覧、コマ枠の通過順選択、前後ボタンが同じ選択状態へつながる。省略方法を変えた場合も、元の経路上の位置を基準に選択を引き継ぐ。

全体地図は道路と生成経路を固定データから描き、選択中の次区間を朱色で示す。地図の表示幅/高さに合わせて描画領域を調整し、重要地点の文字やマーカーはズーム・表示幅に応じて読みやすい大きさを保つ。道路の点列・距離・通過順を編集するものではない。

重要地点は、道路上の到達点へ名称付きのS（スタート）・G（ゴール）・CP（チェックポイント）を表示する。訪問順ラベルの番号を使い、経由地も区別する。複数の訪問が完全に同じ道路上の位置ならS/G等をまとめ、押すたびに該当する通過順のコマへ移る。近いだけの別地点はまとめない。

施設の代表位置は別の小さな点と点線で示す。重要地点ラベルの引出線や施設までの点線は、施設への歩行経路・安全な待機場所・確認済みの入口を意味しない。凡例と説明を地図の近くに残す。

## 維持する条件

- 下書きは1件、保存コースは複数。保存成功時だけ下書きを空にする。
- 訪問順・最短経路・コマの形状・拡大/参照図・AI補助・目印採否・保存版の固定を維持する。
- 採否を保存する前はコース保存を無効にし、未保存の変更を警告する。
- 保存は公開と別操作。公開/停止/再公開/削除の確認と競合処理を維持する。
- 既存API・SQLite v8・ローカル採否保存・参加者画面・道路/画像/モデルを変更しない。
- 依存・環境変数・外部取得・AWS操作は追加しない。

開発ビルドでも主要画面の初期表示・操作を確認した。開発中の全フロー検査は、公開後の再読込みを待たず押していた待機条件と、公開停止画面の既存仕様（200＋停止案内）を404とする検査側の誤認を修正し、最終フローは本番ビルドで完了した。隔離コピーのビルドには、複数lockfileから作業ルートを推定するNext.jsの警告が出るが、型チェック・ビルド・HTTP/ブラウザ検査は成功した。

実装中の検査で、SVGのtitleに分けて渡した説明文によるSSR/ブラウザの不一致を検出した。説明文を単一の文字列にまとめ、同じ画面の初期表示をブラウザで再確認済み。また、常時表示の名称を従来の選択処理で閉じないように修正した。
