## 1. 読み方・進め方

- 優先度はP0（不確実性解消・着手条件）、P1（段階ごとの必須体験）、P2（推奨・検討機能）。同じ優先度は依存関係と記載順を基本とする。要件自体の「必須／推奨／検討」と、開発順の優先度は区別する。
- 状態は「完了（承認済み）」「実装・検証済み・レビュー待ち」「未着手・Phase承認待ち」「未着手・前提待ち」「候補・採否未決定」。着手時に「実施中」へ更新し、承認・実装・検証の実態に合わせて記録する。
- 1タスクは一つの検証またはユーザー価値に絞る。設計 → 実装または文書化 → 必要な検証 → 差分レビュー → コミット → 報告・停止を基本とし、次のタスクは人間の指示を待つ。
- 重要な選定とフェーズ移行は承認後。設計書のHは仮定、Q・Dは未決定事項であり、バックログに記載しただけでは確定しない。
- ドキュメントはdocs/、PoCはpoc/、機能はfeature/などのブランチを使う。mainへのマージ、push、PR作成、AWS利用・デプロイは今回の対象外。
- Phase 2を最も詳しくし、Phase 3以降はストーリーの概略にとどめる。前段の検証で分割・並べ替えを見直す。
