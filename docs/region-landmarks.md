# 地域全体の事前取得・128×128切り抜き・外部取得禁止（P2-12）

2026-11-12。ユーザーがMapillary取得/画像処理を開発PCのバッチへ移し、Webアプリは静的索引の参照と運営者の採否保存だけを行う方針を明示承認した。切り抜きは128×128。OSM背景タイルの通常表示は従来どおり別の外部通信である。

## 成果物と対象

対象は固定道路データの三崎・城ヶ島周辺（南35.122/西139.604/北35.16/東139.642）。現在のコマ生成と同じ「歩行グラフにある点で物理的な枝が3本以上」の基準で1,326地点。近接した別のOSM分岐は統合しない。

- 全1,326地点の取得成功。未取得/ページ上限による保留0地点。
- 重複排除した地物1,460件。停止/横断等の記号と、看板/広告/バナー等の固有物。
- 128×128 PNGの切り抜き439件、合計7,232,076 bytes（約7.23MB）。
- 静的索引1,186,522 bytes（約1.19MB）。地物ID/座標/分類、分岐との対応、画像ID/作者/撮影日/検出領域/ハッシュと配布条件を記録。
- 写真の探索対象590候補、品質条件に合う画像なし153候補。以前のサンプルで取得済みの固有物も含めて439件を配布する。
- 元の街路写真はGit対象外の開発用キャッシュへ残す。公開物を切り抜きへ置き換え、旧デモ原画像9枚はリポジトリから除いた。

全分岐を問い合わせたことは、全地点に識別可能な写真があるという意味ではない。画像/検出がない、小さすぎる、未知の種類は補作しない。停止/横断の初期採用、階段必須、写真の初期不採用を継続する。

## 開発PCで実行する

~~~powershell
npm.cmd ci
npm.cmd run landmarks:region -- --fetch
npm.cmd run landmarks:region -- --offline
~~~

.env.localのMAPILLARY_ACCESS_TOKENを読む。値を引数/URL/ログへ書かず、Client secret・AWSは不要。公開環境の通常起動/ビルドには設定しない。

--fetchは未取得分から再開する。--offlineは外部通信せず保存済み情報から同じ索引/PNGを生成する。最終形式で連続2回のオフライン生成に成功し、Graph/画像取得0回・同じcontentHashと画像バイトを確認した。

小範囲の予備取得を除く全地域の実取得はGraph 1,853回・画像423回。画面表示やルート生成で繰り返さない。対象/保存件数を制限し3並列で処理、認可/レート制限や複数の通信失敗で停止する。完了済み結果は保存し、未完了/エラー時は既存の公開用索引を上書きしない。

保存先はLANDMARK_REGION_DIR（既定.local-data/landmark-region）。raw配下に必要なJSON・元写真・品質不足結果を保存する。署名付きCDN URL・トークン・外部応答本文は保存/表示しない。従来のLANDMARK_POC_DIRやDBを変更しない。

--max-junctions / --max-photosは少数検証用。--reportは取得/公開用書出しをせず調べる。--allow-partialは未取得のある試験索引を明示生成する開発用で、通常配布には使わない。--fetchと--offlineの併用や範囲外の数値を拒否する。

## 索引と切り抜き

[分岐列挙](../lib/landmarks/region-source.ts)で固定道路ハッシュ/地点を確定し、各中心の半径32mを最大2ページまで取得する。既存の分類/品質条件を継続する。地物IDで候補を共有し、各分岐の近い店舗看板を優先して最大3候補の写真を計画する。撮影位置を地物位置に流用しない。

[Sharp](https://sharp.pixelplumbing.com/api-resize/) 0.35.5で開発PCだけで処理する。Next.jsで導入済みの版を開発用直接依存として明示した。検出矩形を切り抜き、縦横比を保って128×128へ収め、余白を透明にする。生成AI・背景除去・形状補完は行わない。小さな領域を拡大しても情報量が増えるわけではない。

PNGのSHA-256をファイル名にし、同じ画像バイトを共有する。元画像ID・作者/撮影日・検出範囲・処理版を追跡でき、EXIFを配布画像へ引き継がない。索引は一時ファイルから置換する。未参照PNGの自動削除は行わない。

- [公開索引](../public/landmarks/miura-v1/manifest.json)
- [作者一覧と利用条件](../public/landmarks/miura-v1/NOTICE.md)

画像は[CC BY-SAの説明](https://help.mapillary.com/hc/en-us/articles/115001770409-CC-BY-SA-license-for-open-data)、派生地物は[ODbLの説明](https://help.mapillary.com/hc/en-us/articles/115001777705-OpenStreetMap-compatibility)を継続する。画像/作者・改変・ライセンスを表示し、対象データベース全体を索引で配布する。詳細API規約は調査環境ではログイン画面で、無制限の取得/保持条件を包括確認したものではない。

## Webアプリの動作

[静的座標索引](../lib/landmarks/bundled.ts)から周辺候補を探す。順序/ルートを変えても配布済み地物だけを検索する。挿入した道路到達点など、分岐中心と一致しない点も検索できる。取得範囲の網羅性を保証できない位置はpartial、範囲外は対象外として示す。

トークンがWeb環境にあっても取得しない。取得ボタン/自動取得を除き、prepare/photoのPOSTは403 external-fetch-disabled。MapillaryクライアントをWeb処理から参照しない。ルート/コマ生成、保存/公開の閲覧もMapillaryを呼ばない。

生成済みPNGを静的配信し、ブラウザの元写真取得/Canvas切り抜きを廃止する。候補欄では128px、コマ上では既存の記号領域に縮小する。元写真は利用者が明示して開く出典リンクで確認する。

APIキャッシュの新旧/破損を候補へ混ぜず、配布版だけを読む。運営者の採否は従来の専用保存先へ保存する。通常の保存/公開版への写真反映、SQLite/AWSの保存先選定・デプロイは後続。

取得対象の1,326分岐のうち、今回の対象分類に当たる地物が得られたのは491地点、30m内に配布済み写真候補を持つのは405地点。全分岐を問い合わせても、Mapillaryの撮影/検出状況によって候補がない地点がある。撮影日は2015-11-29〜2026-05-25で、現地の最新状況を保証しない。

最終確認で、モバイルの旧64px列指定と、Node/ブラウザの微小な数学関数差による目印SVGのhydration警告を検出した。128pxの列表示と、道路と同じ小数3桁の描画座標へ修正し、最終の両モードでは警告/表示エラー0件を確認した。道路の角度・枝/距離・元の地物座標は変更していない。

現地/スマホ実機、通常の保存/公開版への採用写真統合、AWSの配信/永続化検証は未実施。
