# ADR-016：下書き1件と複数の保存済みコースを分ける

- 日付：2026-11-09
- 状態：ユーザーが「A：下書き1件＋保存済みコース複数（推奨）」を明示承認。P4-06bとして実装。
- 関連：[最小仕様](../saved-course-plan.md)、[実装・検証記録16節](../operator-app.md#p4-06b)、[作業中下書き](011-working-rally-draft.md)。

## 決定

作業中下書きは従来の1件を維持する。運営者が生成結果を確認して「この結果を保存」を選んだとき、複数の非公開コースとして追加保存する。保存後も下書きと補正は残し、別のコース作成を続けられる。保存済みの上書き・編集・削除・下書きへの復元/複製は今回追加しない。B案の最新1件だけへの上書きは採用しない。

保存は、元の下書き/選択スポットの情報・到達点補正、出典/ハッシュ、計算済み経路・区間距離・訪問順・全コマ・元辺と方向・全補足情報・30m参照形状を一つの形式v1へ固定する。後の台帳・下書き・道路変更を自動反映しない。保留や現地未確認の注意も残す。

/operator/coursesの一覧と/operator/courses/[id]の読取詳細は、現在の台帳や生成器を呼ばず、保存形式と指紋を検証して当時の値を表示する。コマ選択・地図連動・表示レイヤー・画面幅に応じた拡大は使えるが、表示状態は保存しない。詳細から補正/再生成を実行せず、別の作業中下書きへのリンクであることを明示する。

## 保存要求と同一性

クライアントは表示中の結果のSHA-256指紋と、下書き/補正の版・道路/周辺情報のハッシュだけをPOST /api/operator/coursesへ送る。既存の同一Origin/JSON/16KiB上限・no-storeを使い、クライアントの計算済みモデルを受け取らない。

サーバーで現在の入力から再計算して表示時の指紋と照合し、保存直前のトランザクションでも選択スポット・下書き・補正の変化を確認する。変更があれば409で止め、表示中のモデルを残す。無関係なスポットの変更だけでは拒否しない。到達不能・全区間0mは保存しない。

同じ指紋は一意制約で1件とし、連打/同時保存/応答消失の再送で元のID・保存日時を返す。すでに保存された同じ要求は、現在の台帳/下書きが変わっていても元の記録を返す。別内容は追加し、他の保存を上書きしない。

## ローカル保存と限界

既存SQLiteをv4からv5へトランザクション移行し、saved_courses表（ID・一意な指紋・JSON値）を追加する。旧スポット編集/削除・下書き・補正を保持する。モデルの形式v1、DB全体v5、参加者進捗v3は独立した版。新しい依存は追加しない。

IDはcourse-にUUIDv4を付ける。正規化JSONはオブジェクトキーを安定順にし、配列の順を保つ。生成器識別子はoperator-preview-v1。1件のペイロードは最大8MiBとし、超える場合に枝や目印を省略して保存しない。保存記録は構造・版・ID・指紋・距離/コマ/訪問との整合を検証する。破損/未対応形式/DB移行失敗を黙って初期化したり、最新の生成値で置き換えたりしない。

一覧は概要のみを画面へ渡すが、読取時に各記録全体を検証する。件数上限/ページ分割は設けておらず、多数の大きな保存の性能評価は後続。保存済みJSONの将来形式への移行・削除/バックアップ運用も後続とする。

すべてローカルの非公開確認用。入口・通路・安全性の確認や公開承認を意味しない。参加者側・QR/クーポン・認証/認可・公開済みコース版/参加中データとの整合は今回含めない。AWS利用/サービス選定/デプロイは別途承認し、SQLiteをAmplify Hostingの永続DBと扱わない。
