# ADR-004：固定ラリーの匿名参加開始をタブ内で保存する

- 日付：2026-11-07
- 状態：承認済み。P3-02の質問に対するユーザーの「A：同じタブ内に保存（推奨）」を受領。
- 対象：ローカルの固定デモ。実際の参加受付・公開・AWSバックエンドの選定は含まない。
- 関連：[設計Q-13/D-03](../design.md)、[P3-02](../backlog.md)、[参加者画面](../participant-app.md)

2026-11-08追記：本書の開始記録のみの説明はP3-02時点のもの。保持方式は継続し、P3-04aのデモ達成保存と旧形式の引継ぎは、別途承認した[ADR-005](005-demo-checkpoint-recording.md)に記録する。

## 背景

U-03の開始状態を扱うには参加の識別と保持範囲が必要。ユーザーは対象AWS環境でCognitoを利用できないとし、ハッカソンではログインなし・画面切替を希望している。現地の安全性やチェックポイントの到達判定は未確認で、今回は開発用の開始デモに限定する。

## 決定

ログイン・個人情報入力なしで、ブラウザが生成するランダムなUUID v4の参加ID、開始日時、対象ラリーIDと内容の版、保存形式の版をsessionStorageへ保存する。開始はユーザーのボタン操作で行い、ページを閲覧しただけでは参加を作らない。

同じタブ・同じoriginの再読込みとページ間の移動では同じ開始記録を使う。通常はタブを閉じるまでの一時保存。長期保持・端末間の引継ぎ・複数タブの共有は提供しない。別ポート/ホストも別のoriginになる。タブの複製・openerやブラウザの復元ではコピー/復元される場合があり、タブ終了時の確実な消去や人の一意性を保証しない。

現在のコースに結びつく版を保存し、異なる版や壊れた記録は継続しない。古い記録の置換は明示的な新規開始でのみ行う。保存アクセスの拒否・容量不足・書込み/読戻し失敗時は開始成功と表示せず、再試行を示す。繰り返しの開始操作は既存の有効記録を再利用する。

ブラウザ保存への依存は小さな関数の入出力へ分離し、UI/進行処理へクラウドSDKや汎用ストレージ基盤を導入しない。

## 比較・限界

| 候補 | 評価 |
| --- | --- |
| 画面のメモリーのみ | 最小だが再読込みで開始状態を失う。今回は不採用。 |
| sessionStorage | 同じタブでの再表示を試せる一時記録として採用。ブラウザの設定や消去に依存する。 |
| localStorage | タブ終了後の保持・期限・複数タブの整合を別に決める必要があり、今回は不採用。 |
| ローカルDB/サーバー保存 | 本番相当の永続化・共有が必要な時に比較する。今回の匿名・タブ内デモには導入しない。 |

参加IDは本人確認やアクセス権を示すトークンではない。記録は開発者ツールから改変でき、チェックポイント達成・不正対策・特典の保証には使えない。U-10の一般的な中断復元やCP-06の達成記録の保存を実装済みとは扱わない。P3-04以降や実利用の公開前に必要な保存・権限・到達判定を別途確認する。

Web Storageの挙動と失敗条件は[WHATWG HTML Standard](https://html.spec.whatwg.org/multipage/webstorage.html)と[MDN sessionStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/sessionStorage)を2026-11-07に確認した。ローカルでの検証はAWS配信の保証ではない。
