# ADR-017：公開したコースを参加者が利用する流れを優先する

- 日付：2026-11-10
- 状態：開発順の変更はユーザーの「コマ地図の精度向上よりアプリに必要な機能、参加者側への公開を実装したい」という指示に基づく。公開/参加者の個別仕様は[仕様案](../publication-plan.md)で採用確認する。
- 関連：[ADR-007](007-operator-first-development.md)、[ADR-016](016-saved-course-snapshots.md)、[バックログ](../backlog.md#publication-flow)。

## 今回確定する開発順

コマ地図の追加精度向上や近接コマの統合、未接続地点の調査は優先タスクから外し、運営者が作成・保存したコースを参加者へ掲載して利用する一連の体験を先に進める。重大な表示不具合の修正は引き続き行う。

ADR-007による参加者側の一括保留を、公開コースの一覧/詳細・開始/コマ閲覧を再開する方向へ更新する。固定コースのデモだけでなく、運営者が選んだ異なるコースを利用できることを目指す。QR・クーポンの要件は残し、最初の公開ストーリーへ一括して含めない。Phase 3/4や全MVPの完成とはしない。

## 今回の指示で確定しないこと

公開する版と更新/掲載解除、参加中データ、記録する確認項目、可変コースの達成/ゴール条件、参加者への拡大図の適用範囲は必要な深さで具体化し、重要な判断は採用確認する。今回の方向性の指示だけで、これらの未決定を承認済みとしない。

AWS利用/有料リソース・外部へのデプロイ、Cognito等の新しい認証、mainへのマージ/push/PR作成の承認は含まない。現在はAWSアカウント不要のローカル実行を維持する。既存の「画面切替は認可ではない」という境界も維持する。

公開と参加者画面の採用範囲を具体化してから、UI/API/保存を一つの小さなストーリーで実装する。人の確認履歴や全公開運用を大きな基盤として先に作ることは避ける。各タスク後の検証・レビュー・コミット・停止は継続する。
