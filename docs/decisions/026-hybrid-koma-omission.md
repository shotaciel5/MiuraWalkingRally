# ADR-026：③ ルール＋学習済みモデルによる追加保持を標準にする

- 状態：ユーザー承認済み・実装
- 日付：2026-11-13
- 根拠：「資料が候補としているのが③なら、このアプリでも③を用いてほしいです。」

## 決定

ADR-025のルール単独標準を、新規生成について③へ変更する。ルールが残すコマは必ず残し、省略候補にだけcorrected-candidateのRandomForestを適用する。同枝数・最大角度差30度以下・保持スコア0.2以上で追加保持し、比較相手の復帰に伴う再走査を行う。不明/失敗は保持へ倒す。アプリ側の必須/手動編集保護を継続する。

350特徴・float32木比較をTypeScript/Nodeへ移し、学習済み200木JSONを同梱する。原本ハッシュを固定し、凍結資料と697例の特徴量/スコア/運用判断の一致を検証する。Pythonは検証用のみで、実行時の外部APIや新しいサービス/依存は導入しない。

省略plan v2にモデル版/条件/各ペアの判断を固定する。保存payload v3とSQLite v7を維持し、古いplan v1/既存公開版を再推論しない。新規はAI補助を既定とし、設定内のルール比較/全交差点と、保存済みの読取専用切替を用意する。

## 理由と限界

元資料の運用候補をそのまま採用し、AWS移行時のPythonランタイム追加を避ける。純粋な選別とサーバーの推論を分け、旧版を保つ。コード/モデル/出典は残し、受領資料は変更しない。

移植一致は現地精度の保証ではない。旧1.5%を本モデル/三浦市の実績として使わない。再学習・閾値調整・実機/現地の独立評価とAWS検証は後続。[仕様・検証](../hybrid-koma-omission.md)。
