# ADR-012：道路範囲の拡張と自動接続候補、運営者指定の訪問順

- 日付：2026-11-09
- 状態：道路拡張の先行・訪問順B案・近傍道路への自動対応付けの要望をユーザーが承認。候補表示P4-03b-1は次の着手指示で承認済み。候補点の計算基礎P4-03b-2は後述。
- 対象：P4-03b-1。ルート/コマの可変生成は後続。
- 関連：[ADR-001](001-local-route-poc.md)、[ADR-011](011-working-rally-draft.md)、[要件](../requirements.md)

## 背景と決定

従来は仮到達点のある3地点で生成を先に実装する予定だった。ユーザーは道路・到達点の拡張を先に進め、新規スポットにも道路IDの手設定を求めない方針を希望した。また、訪問順まで総距離を最小化せず、下書きの並びを使うB案を選択した。

1. 三崎・城ヶ島の初期178件を覆う範囲へ固定OSMデータを拡張する。既存PoCは別に保持する。
2. 下書きの開始 → 途中地点の表示順 → 終了を訪問順とする。地点間の徒歩経路は経路探索アルゴリズムで求め、訪問順の最適化は導入しない。R-04とADR-011の「仮の並び」を更新する。
3. 既存の歩行ルールで許容する道路線分へ施設位置を射影し、最も近い候補を自動提示する。歩道を必須にせず、明示的な歩行禁止・立入制限・未対応条件を尊重する。
4. 初期・追加・位置編集後のスポットに同じ計算を用いる。道路IDの入力や、スポットごとの事前手設定は不要とする。

## 今回の実装詳細

固定範囲は南35.122・西139.604・北35.160・東139.642。Overpassへの有界クエリ1回で道路・建物・目印・標識を取得した。全情報約7.1MBから道路・必要ノード・制約関係だけの約0.88MBをオフライン導出し、候補APIは後者を使う。出典・取得時点・原応答と固定データのハッシュを保存し、通常の起動/テスト/ビルド/閲覧では取得しない。背景タイルは従来の別通信である。

道路グラフの許容された有向辺だけを対象とし、線分の両端座標を変えずに射影点を求める。地域内の緯度経度を緯度の余弦で補正する平面近似で射影し、施設から候補への直線距離は球面距離で算出する。同距離は道路ID・両端ノードIDの数値順で決め、同じデータ・座標なら同じ結果になる。取得データの改変はハッシュ不整合として検出する。

GET /api/operator/spots/connection?id=... は有効な台帳の現在の版/座標を読み、候補と出典を返す。候補は派生値としDBに保存しない。UIはスポットID・版・施設座標を照合し、選択変更や編集前の古い結果を表示しない。ネットワーク/取得失敗時もスポット詳細と下書きを保持し、再試行できる。

## 限界と後続

「接続候補・未確認」であり、入口・敷地内通路・海/崖/建物を挟まないこと・現地安全性・他地点との到達可能性を保証しない。地図の点線は直線の位置関係であり、徒歩ルートではない。道路との距離が短いことを安全判定に使わず、任意の距離閾値で確認済みにしない。

178件すべてに候補はあるが、生成可能な178地点が確定したわけではない。既存PoCの到達点3件や確認状態は保持し「既存PoC基準」と明示する。候補点を経路グラフへ組み込む処理、未接続/到達不能の扱い、候補の採否・修正方法、可変ルート/コマ・拡張補足情報の描画は後続の小タスク。保存/公開・参加者側の追加開発・AWS操作へは進まない。

OSMの[帰属・利用条件](https://www.openstreetmap.org/copyright)を保持する。公開Overpassは[共有資源](https://dev.overpass-api.de/overpass-doc/en/preface/commons.html)として手動の有界取得に限定する。[entranceタグ](https://wiki.openstreetmap.org/wiki/Key:entrance)の入口情報と施設の代表点を同一視しない。
