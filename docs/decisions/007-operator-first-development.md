# ADR-007：参加者側を保留し、初期スポットと運営側の生成機能を優先する

- 日付：2026-11-08
- 状態：方針承認済み。ユーザーの「その方向性で次お願いします」と初期スポット充実・追加/削除/編集の要望を受領。
- 対象：ローカル開発の優先順位とPhase 4への先行着手。個々の保存方式・削除方式・データ範囲/件数の採用決定は含まない。
- 関連：[要件](../requirements.md)、[設計18節](../design.md#operator-first-design)、[バックログ5節](../backlog.md#operator-first)、[ADR-005](005-demo-checkpoint-recording.md)、[ADR-006](006-demo-goal.md)

## 決定と理由

Phase 3の残作業を保留し、運営者がスポットを選び、ルートとコマ地図を生成・確認する中核機能を優先する。固定コースの参加者向けデモは維持する。スポットの組合せを変えても生成が成立するかを、クーポンやQRの追加より先に検証する。

初期状態から選べるスポットをなるべく多く用意し、運営者が初期/追加スポットを追加・編集・削除できるようにする。今回の要望をSP-07と初期データの要件に反映する。初期候補の収集を早め、一覧・位置確認・追加/編集・削除を小さく実装し、選択/生成/プレビューへつなぐ。

初期候補は三崎・城ヶ島を中心に調べる。具体的な採用件数・取得範囲・情報源は出典/利用条件・座標・重複・道路接続を確認して具体化する。スポット候補の登録とルート生成に使える状態を区別し、未検証の入口や接続を推測しない。

## 保留と引き継ぐ条件

P3-06クーポン、P3-04b QR、P3-07通し確認、参加者側の追加改善を保留する。運営側の認証・特典設定や実公開も後続とする。QR必須やクーポン等の要件は維持し、Phase 3と両利用者を含むMVPを未完了として扱う。再開時期は運営側の進捗をレビューして決める。

この決定は、従来のPhase 3完了後にPhase 4へ進む計画と、ADR-005の後続順序を変更する。ユーザーの今回の明示承認を根拠とし、AGENTS.mdの各タスク後のレビュー・コミット・停止、重要な技術選定の承認、mainへのマージ/push/公開の制限は継続する。

## 未決定と今回の範囲

運営データのローカル保存、保持範囲、必須入力項目、初期データ更新、利用中スポットの削除、生成時の訪問順の決定方法は、対応する実装前に必要な深さで具体化する。運営者の編集/削除を初期データ再適用で取り消さず、既存ラリーや参加記録を壊さないことを検証条件とする。

今回はP4-00として要件・計画・決定記録だけを更新する。データの取得/拡張やアプリ実装、AWS操作は行わない。次の提案はP4-01aの初期スポット候補収集・整理。実装タスクの完了や実地安全性の承認は今回に含まない。
