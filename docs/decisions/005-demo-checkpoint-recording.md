# ADR-005：デモ用ボタンで達成記録を先に検証する

- 日付：2026-11-08
- 状態：承認済み。ユーザーの「ハイお願いします。引き続き進めてください」で提案を承認。
- 対象：P3-04aのローカル開発用デモ。QR・実際の訪問確認・公開用の不正対策は含まない。
- 関連：[バックログ](../backlog.md)、[保存方式ADR-004](004-local-participation.md)、[参加者画面](../participant-app.md)

## 決定と順序

P3-04を、デモ用ボタンでの達成記録P3-04aとQR認証P3-04bへ分割する。ボタン → ゴール → クーポン → QR追加 → 通し確認の順に進め、各タスク後に停止する。要件CP-02のQR必須は残し、実装順だけを変更する。

P3-04aではC1/C2の「デモ用：達成にする」で、対象ラリー・版・参加IDに対応する達成記録をタブ内のsessionStorageへ保存する。コマ/写真の閲覧や末尾の表示だけでは達成・ゴールを記録しない。デモの試験ではボタンを任意順に操作できるものとし、正式な認証順序Q-04を確定しない。

ボタンからの確認入力と、達成を追記する処理を分ける。後でQRを追加する際も、対象・順序等の検証に成功した入力を同じ記録処理へ渡す。先回りした認証基盤や汎用アダプタ群は作らない。

## 記録と保持

参加形式v2に、checkpointId・method（今回はdemo-button）・recordedAtの達成配列を追加する。同じ対象への再処理では最初の記録時刻と達成数を変えない。S/G/W1・未知の地点・版違い・別参加への記録は拒否する。

既存の形式v1は同じ参加ID/開始日時と空の達成配列として読み込み、閲覧だけでは保存し直さない。最初の達成操作でv2を書き込む。コース内容の版は今回変更しない。古い形式の余分な達成フィールドを取り込まず、壊れた記録は継続しない。

保存アクセス拒否・書込み/読戻し失敗を成功扱いせず、再確認/再試行を示す。同じタブでの再読込みやページ移動では達成記録を復元するが、閲覧コマ位置は引き続き画面内のみで、再読込みで先頭へ戻す。

## 限界と後続

画面では「デモ達成済み」とし、実際の到着を証明しないことを明示する。記録は利用者が変更・消去でき、タブ複製やブラウザ復元でコピーされる場合もある。実際のクーポン発行や本人確認の信頼できる証拠にはしない。

QRの形式・配布・対象/順序の検証・誤読/権限拒否・コピー対策はP3-04bで確認する。ゴール条件・特典条件も各タスクで別途承認する。AWS・DB・ログイン・クラウドSDKの採用は今回行わない。
