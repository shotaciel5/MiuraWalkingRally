## 1. 今回の範囲と情報源

P4-00後のユーザーの「次お願いします」で着手し、「神社だけでなく、市場・カフェ・土産・小さな名所など広く」という指示を反映した。既存採用のOSM/Overpassを使い、三崎・城ヶ島周辺の固定候補を作る。運営画面、保存DB、広域道路網の置換、参加者側の追加機能は今回の対象外。

[OSMの利用条件](https://www.openstreetmap.org/copyright)と[Overpassの運用方針](https://dev.overpass-api.de/overpass-doc/en/preface/commons.html)を再確認。採用済みの出典・固定取得方式を維持し、新しい有料サービスやAPIキーを導入していない。公式観光案内等は名称/用途や不足候補の照合に用い、説明文・写真・他社地図の座標を転載していない。

2026-11-08 16:00:21.820 JSTに、南35.125・西139.608・北35.157・東139.638の矩形を1回取得した。OSM基準時刻は15:59:20 JST。取得原本106,744 bytes、ノード238・ウェイ55・リレーション2の計295件。正規化後は73,388 bytes。クエリ・日時・正規化内容と原本/固定データのハッシュは[source.json](../data/spots/source.json)に記録した。

## 3. 保留・除外と追加調査

295件は候補178・保留15・除外102へ分けた。手作業の採否を[review.json](../data/spots/review.json)、生成した各IDと理由を[initial-spots.json](../data/spots/initial-spots.json)に保存している。

- 保留15件：近接した同名店舗のノード/ウェイ、マツウラ2件、同じ一角の同名石塔、名称特定が難しい飲食店、旧灯台跡等。
- 除外102件：案内看板43件、学校/病院/事業所など今回の分類外58件、代表点が取得範囲外の広域地物1件。案内看板を施設本体として件数に加えていない。
- 「うらりカフェ」は、[施設公式の「うらりテイスト」案内](https://www.umigyo.co.jp/marche/marche-yasai.html)との名称/位置の対応を確認するまで保留。営業終了と断定せず、名前や座標を推測して置き換えない。
- 同名6グループは別IDで残した。別支店や三崎/城ヶ島の海南神社を名前だけで統合しない。

次の3件は公式掲載を確認したが、今回のOSMスナップショットで名称と位置の対応を確認できなかった。座標nullの追加調査リストとして別途保持し、候補178件にも取得295件にも加えていない。

スポットのIDは元OSM要素から決め、S/G/C1等の訪問役割と分けた。同じスポットを開始と終了に設定できる形を妨げない。距離の近さから接続ノードを作らず、承認済みの仮ノード以外は生成に使える到達点を設定していない。既存PoCの道路・補足情報・写真・31コマと参加者コース版は変更していない。

## 5. 実装・検証と自己レビュー

分類/正規化を[initial-catalog.ts](../lib/spots/initial-catalog.ts)、取得とオフライン生成を[scripts](../scripts/build-initial-spots.mjs)へ分けた。起動・テスト・再生成に外部APIを要求しない。ID/タグ/座標の検査、連絡先/編集者情報の除去、名称不明・休止/制限タグ・範囲外の扱い、同名の非統合、古い採否参照の拒否を検証した。新しい依存ライブラリ・DB・クラウドSDKは不要。

| 区分 | 結果 |
| --- | --- |
| 型検査 | npm run typecheck成功。 |
| 単体テスト | npm test：165件成功・失敗0。従来151件に、分類/正規化/座標/重複/除外・保留/出典/固定生成/到達点等の14件を追加。 |
| 再現性 | npm run spots:check成功。固定入力と採否記録から候補・理由・集計が一致。 |
| 本番ビルド | 作業用コピーでnpm run build成功。起動中の開発サーバーと.nextを共有せず、同じコード/固定データと既存依存で検証。コピーと親のlockfileによるworkspace root推定警告あり。 |
| 文書/既存データ | 文書参照・差分と既存OSMスナップショットのハッシュを確認。 |
| 未実施 | 新しい運営画面/DB/CRUD、道路の範囲拡張・各候補の現地/営業/入口確認、HTTP/ブラウザの再検証、AWS配信。画面コードは変更していない。 |

候補の数と「公開/生成できる地点数」を区別し、推測した入口や座標で件数を増やしていない。元データ・除外/保留理由・手作業の対応を追跡でき、既存PoCと参加者側の記録を変えていないことを自己レビューした。

feature/initial-spot-catalogでコミットしてレビューを求め、P4-01aで停止する。次の提案はP4-01bの初期スポット一覧と位置確認。ローカル保存方式・必須入力・利用中スポットの削除はP4-01c/dで確認し、今回は実装しない。
