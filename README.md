# 三浦市ウォーキングラリー

三崎・城ヶ島のスポット/経由地を選んで、ルートとコマ地図を生成・保存・公開するWebアプリです。参加者は一覧から開始し、地図をたどってチェックポイントで各自のスマホカメラを使い写真を撮り、ゴールで見せます。コマ画面は地図と移動操作を中心にし、該当コマでだけ地点名と撮影案内を表示します。QR/AI認証・画像アップロード/判定・クーポン/特典は対象外です。現地の入口・通行・安全性と、ゴールの受付運用は確認待ちです。

起動後の / はアプリ紹介のトップです。「参加する」から /courses、「コースをつくる」から /operator に進めます。

要件は [docs/requirements.md](docs/requirements.md)、設計は [docs/design.md](docs/design.md)、進捗は [docs/backlog.md](docs/backlog.md)、PoCの検証記録は [docs/poc-route-map.md](docs/poc-route-map.md) を参照してください。

[P2-07の総合レビュー](docs/poc-route-map.md#p2-07)後、2026-11-07のユーザー指示で、固定データを使うPhase 3のローカル画面開発とP3-01への着手を承認済みです。[参加者画面の実装・検証記録](docs/participant-app.md)に今回の範囲を記録しています。現地安全性・入口・実測精度/読解と手動参照10コマは保留を継続します。現在の公開はローカルアプリ内への掲載で、AWS/インターネットへのデプロイはしていません。

[運営側を優先する開発方針](docs/decisions/007-operator-first-development.md)に従い、三崎・城ヶ島周辺の[初期スポット候補178件](docs/spot-catalog.md)を固定データへ保存しました。市場/鮮魚/産直8件、カフェ5件、飲食43件、土産2件、公園・景観・店舗等を含みます。候補全件の営業現況・現地安全性は未確認です。既存PoCの仮到達点あり3件、入口未確認83件、既存道路範囲外92件として扱います。[スポット管理画面](docs/operator-app.md)は初期表示24件（三崎周辺/城ヶ島周辺各12件）から全178件へ切り替えられます。ピンと一覧の選択、6ジャンル・エリア・名前での絞り込み、代表位置と確認状態の詳細を表示します。追加/編集はPC上のSQLiteへ保存します。削除は確認後に削除済みを保存します。ラリー下書きで地点を選択・保存できます。スポット選択時は拡張道路から近傍候補と直線距離を自動表示し、追加/位置編集後も再計算します。入口・接続は未確認です。訪問順は運営者が下書きに並べた順を使い、保存後にルート・コマの生成プレビューを確認できます。QR/AI認証とクーポンは要件v0.3から撤回しています。

初期データの再現確認は、サーバーやネット接続なしで実行できます。[出典と再取得手順](data/spots/README.md)を参照してください。

~~~text
npm run spots:build
npm run spots:check
~~~

三崎・城ヶ島の[拡張道路・周辺情報](data/miura-expanded/README.md)は別の固定データで、通常の実行時に取得しません。道路の導出と整合確認はオフラインで実行できます。

~~~text
npm run roads:build
npm run roads:check
~~~

道路上候補を用いる計算の確認は、次のコマンドで実行できます。固定初期178件の接続グループと代表経路を出力し、実DBや下書きは変更しません。道路上の距離と施設→道路の直線距離は別です。最大163地点が相互に到達できるグループに入り、別の15地点は接続/制約などの確認が必要です。詳しくは[検証記録9節](docs/operator-app.md#p4-03b-2)を参照してください。画面上の生成プレビューは下書き保存後に利用できます。

~~~text
npm run connections:report
~~~

## 前提

- Node.js **24.22.2**、npm **11.19.1**。Node.jsの版は.node-versionにも記録しています。
- Next.js **15.5.29**、React／React DOM **19.3.1**、TypeScript **5.9.3**。直接依存とpackage-lock.jsonで版を固定しています。間接依存のPostCSSは監査結果に基づいて8.5.32へ固定しています（[選定記録](docs/decisions/002-local-web-runtime.md)）。
- 初回の依存取得にはインターネットが必要です。起動・テスト・ビルドにAWSアカウント、認証情報、AWS CLI、Amplify sandbox、APIキーは必要ありません。
- 起動・ビルドに必須の環境変数はありません。.env.exampleにその旨を記載しています。.env.local等はGit対象外です。
- 既存の古いNode.jsが選ばれる場合は、バージョン管理ツール等で上記の版を有効にしてから実行してください。システム全体のNode.js更新はこの作業では行っていません。

このワークスペースのWindows検証用Node.jsは、Git対象外の.tools/node-v24.22.2-win-x64に置いています。存在する場合、そのシェルだけで次のように有効化できます。新規クローンには.toolsは含まれないため、[Node.js公式配布](https://nodejs.org/dist/v24.22.2/)から対象版を用意してください。

~~~powershell
$taskNodeDirectory = (Resolve-Path -LiteralPath ".tools/node-v24.22.2-win-x64").Path
$env:Path = $taskNodeDirectory + ";" + $env:Path
node --version
npm --version
~~~

## ローカルで install → start → test → build

~~~text
npm ci
~~~

package-lock.jsonに従ってインストールします。Node.jsとnpmの対応版は前項を確認してください。

### 開発者向け：旧固定デモ

開始・デモ達成・終了の記録は同じタブのsessionStorageに一時保存し、再読込みや一覧/詳細/PoCの往復でも引き継ぎます。通常はタブを閉じるまでの保持で、端末変更や長期保存はできません。タブ複製やブラウザ復元ではコピー/復元される場合があります。開始時の保存に失敗した場合は開始済みとせず、再試行を表示します。達成・終了の保存を確認できない場合は成功扱いにせず、「保存状態を再確認」を表示します。[承認済みの保存方針](docs/decisions/004-local-participation.md)を参照してください。一般の参加受付・実際の散策には対応していません。

開始後は「前のコマ」「次のコマ」、選択欄、チェックポイント候補一覧からコマを選べます。コマの選択は閲覧操作で、到着や達成の記録にはなりません。C1/C2の「デモ用：達成にする」を押した時だけデモ達成を保存します。実際の到着は確認せず、テストでは任意順に操作できます。同じ対象を繰り返しても最初の記録時刻・達成数は変わりません。閲覧位置は保存せず、再読込みすると同じ開始・デモ達成・終了の記録を読み込み、閲覧コマだけ最初に戻ります。

両チェックポイントをデモ達成にした後、「最後のコマを見る」から31コマ目へ移り、「デモ用：ゴールする」を押すと終了日時を保存します。2/2や最後のコマの表示だけでは終了しません。終了後も地図を閲覧でき、再読込み後は「ゴール結果を見る」で同じ終了結果を表示できます。再操作でも最初の終了時刻を保ちます。クーポンは新方針で対象外です。[承認済みのデモ用ゴール条件](docs/decisions/006-demo-goal.md)を参照してください。

C1海南神社・C2本瑞寺の参考写真を、作者・原典・ライセンスとともに表示します。[写真の出典](public/photos/README.md)を参照してください。現地確認済みの入口・撮影対象ではありません。P3-02以前のコース版では「新しいデモを開始」が必要です。P3-03/P3-04aの記録はID/開始日時/既存の達成を保って読み込み、次の明示的な達成・ゴール操作で保存形式v3へ移します。閲覧だけでは書き換えず、今回コース版は変更していません。[承認済みの順序・保存方針](docs/decisions/005-demo-checkpoint-recording.md)を参照してください。

### 運営者向けの基本操作

スポット管理の背景地図は、承認済みの[Leaflet＋OSM標準タイル](docs/decisions/008-operator-spot-map.md)を使います。表示にはネット接続が必要ですが、背景が読めなくても一覧・詳細は使えます。起動/ビルドにAPIキーやAWSは不要です。地図の表示条件と選択は保存せず、再読込みでデモ表示へ戻ります。現地の入口・営業・安全性は未確認です。


### 運営者のスポット追加・編集・削除

/operator/spotsで「スポットを追加」、または選択した詳細の「このスポットを編集」を使います。名称・カテゴリ・施設位置が必須、説明は任意です。施設位置は地図クリック（オレンジ色の丸）か緯度/経度で指定します。今回は三崎・城ヶ島の既存候補範囲内を対象にします。背景が読めなくても数値入力と一覧を使えます。

変更は標準で.local-data/operator-spots.sqliteへ保存し、タブ/サーバーを閉じても保持します。同じサーバーと保存先を使うブラウザで共有します。初期178件のJSONには書き込まず、保存した追加/編集を重ねます。保存後は全候補へ切り替えて対象を選択します。表示条件は再読込みでデモ表示へ戻ります。未保存のフォーム入力は再読込みでは復元しません。

保存に失敗した場合は入力を残して再試行できます。別の画面で先に編集された場合は上書きを止めるので、入力を控えて「編集をやめる」から最新情報を読み直してください。位置編集は仮到達点との対応を外し、入口/道路接続は確認待ちに戻します。参加者の固定コースや進捗には反映しません。

必要な場合だけ、.env.localへSPOT_DB_PATHを指定して保存先を変えられます（相対パスはプロジェクトルート基準）。起動中なら再起動します。標準の保存先では設定不要です。

~~~dotenv
SPOT_DB_PATH=.local-data/operator-spots.sqlite
~~~

保存ファイルと.env.localはGit対象外です。別の拡張子/場所へ保存する場合も秘密情報や運営データをGitへ追加しないでください。バックアップはアプリを停止して保存ファイルを別途保管します。ファイルの削除/紛失で変更は失われ、自動バックアップ・端末間同期はありません。

このSQLite保存はローカル開発用です。Amplify Hostingで永続保存するにはバックエンドの選定と保存処理の交換が必要です。書込みAPIもローカル同一オリジン向けで、本番の認証/権限は保証しません。[承認された方針](docs/decisions/009-local-spot-editing.md)と[検証記録](docs/operator-app.md#p4-01c)を参照してください。ラリー下書きで地点を選択・保存できます。保存後に生成し、確認した結果を明示保存できます。


スポット削除は、選択した詳細の「このスポットを削除」から行います。確認画面の名称・位置・ID、既存の固定デモコースでの利用状況を確認してください。キャンセルでは保存しません。削除済みとして記録を保持して一覧/地図から外し、再読込みや初期データの再適用でも復活しません。固定デモの使用地点を削除しても、既存コース・参加記録は保持します。復元・完全消去の画面は今回ありません。

別画面で対象が編集されていた場合は削除を止めるため、確認画面から最新の台帳を読み込み、対象を確認し直してください。保存に失敗した場合は対象を残して再試行できます。削除が成功した後に応答だけ失われても、同じ対象での再試行は最初の削除記録を使います。削除済みIDへの遅れた編集は拒否し、自動で復活させません。

現在のSQLiteはv7です。初回読込みでv1〜v6から台帳編集/削除・下書き/補正・保存済み/公開情報を保持して移行し、公開状態と変更版・直近日時を保存します。既存の保存済みコースは自動公開しません。移行前のバックアップはアプリを停止して保存ファイルを保管してください。旧コードへ戻す場合は事前バックアップと対応コードを併せて使います。[削除方針](docs/decisions/010-spot-deletion.md)と[下書き方針](docs/decisions/011-working-rally-draft.md)を参照してください。


### 地点を選んでラリー下書きを保存

/operator/draftを開くか、運営者内の「ラリー下書き」を選びます。作業中の下書きは1件です。名前と開始・終了地点を選び、途中の地点をチェックポイント/経由地へ割り当てて「下書きを保存」を押します。開始と終了は同じスポットを使えます。途中は任意で、役割変更・外す操作・訪問順の上下移動ができます。この並びで巡り、地点間の道順を自動生成する方針です。

地図/一覧・名前/ジャンル/エリアから有効な台帳を選べます。入口未確認・道路範囲外も確認待ちとして保存できます。途中の並びは入力の整理用で、実際の訪問順の自動決定やルート/コマ保存後に生成し、確認した結果を明示保存できます。距離・歩行時間・通行可能の保証はまだありません。

保存した下書きは台帳と同じSQLiteファイルに保持し、再読込み・サーバー再起動で復元します。未保存の変更は画面内だけなので、ページを移動する前に保存してください。台帳の変更/削除を検出したら、最新情報を反映して確認し、削除済みは外すか選び直して保存します。反映だけでは自動保存しません。

別画面で下書きが更新されていた場合は上書きを止めます。入力を控え、「保存済みを読み直す（未保存を破棄）」で最新の保存内容へ戻ってください。保存失敗時は入力を残して再試行できます。既存の参加者向け固定デモとは別の下書きで、参加受付・公開には反映しません。[方針](docs/decisions/011-working-rally-draft.md)と[検証記録](docs/operator-app.md#p4-02)を参照してください。

### 3. 別ターミナルで型検査・単体テスト・HTTPスモークテスト

同じNode.jsを有効にして、同じプロジェクトルートから実行します。

~~~text
npm run typecheck
npm test
npm run test:smoke
~~~

npm run typecheckはNext.jsのルート型を生成してから型検査するため、生成ファイルがない新規クローンでも実行できます。

npm testのスポット保存テストは.tools配下へ使い捨てDBを作り、終了時に削除します。実際の運営台帳は変更しません。追加/編集/削除・プロセス間の保持・再送/競合・保存障害・初期データとの整合・DB移行・固定コースの保持も検査します。

npm testはサーバーやネット接続なしで、歩行ルール・接続・距離・経路探索・固定データに加え、分岐・方向・通過順・候補間距離・コマの投影/切出し/枝の保持・確認待ちを検査します。参加者向けの概算と地点順が同じPoCモデルに対応すること、チェックポイント候補と経由地の役割も検査します。匿名の開始状態、デモ達成・ゴール条件と終了日時、移行/重複/復元、対象・版・参加の整合、不正記録、保存失敗と再試行に加え、参加者向け全コマ/地点の対応と参考写真の整合も検査します。

npm run test:smokeは、起動済みのローカルサーバーに対してトップ・役割入口・公開一覧と開始ページのリンク、版/固定データとの対応、公開条件とサーバー側で開始記録を作らないことを検査します。実際のコマ表示例/帰属、写真/CSSの配信、PoCの互換リダイレクト、不明なパス/ラリーの404応答も検査します。ブラウザの描画・操作や、道順・歩行安全性を検証するテストではありません。

3000番以外で起動した場合は、同じシェルで接続先を指定します。

~~~powershell
$env:SMOKE_BASE_URL = "http://127.0.0.1:3001"
npm run test:smoke
~~~

接続先はローカルHTTPに限定しています。サーバー未起動時はテストが失敗し、起動手順を示します。SMOKE_BASE_URLはテスト用の設定であり、.env.localからの自動読込みは行いません。

### 4. 開発サーバーを停止してビルド

開発サーバーのターミナルでCtrl+Cを押してから実行します。開発サーバーとビルドで.nextを同時に更新しないようにします。

~~~text
npm run build
~~~

### 5. ビルド結果を起動

~~~text
npm start
~~~

npm startは本番用ビルドの起動です。先にnpm run buildが必要です。別ターミナルからnpm run test:smokeでHTTP配信を確認できます。終了時はCtrl+Cで停止します。

## AWS互換性と保守

2026-11-06に、[AWS公式のNext.js対応](https://docs.aws.amazon.com/amplify/latest/userguide/ssr-amplify-support.html)と[Node.jsランタイム対応](https://docs.aws.amazon.com/amplify/latest/userguide/ssr-supported-features.html)を確認し、Next.js 15／Node.js 24の範囲で選定しています。未確認のEdge機能やstreamingには依存せず、固定デモ/PoCは静的ですが、現在の運営/公開コースはNode.jsサーバー処理とSQLiteを使います。AWS配信の互換性・永続保存先は別途検証/選定します。

Next.js 15のセキュリティ更新期限は[公式保守方針](https://nextjs.org/support-policy)で2027-01-31とされています。公開前には、保守対象の版とAmplify Hostingの対応範囲を再確認してください。必要な更新は別タスクとして扱います。

ローカルでのビルド成功はAWS上での動作保証ではありません。AWSリソース、リポジトリ接続、Amplify設定ファイルは今回作成していません。AWS利用可能後に、明示承認を得て最小構成を検証します。

## 歩行ルールの合意

歩道の存在は経路候補にするための必須条件にしません。自動車が通れる一般道路も、歩道なし・歩道情報なしを理由に一律除外しない方針です。一方、明示的な歩行禁止・自動車専用・立入制限等は別に判定します。徒歩専用路を車が通れない理由だけで除外することもありません。

P2-04でこのフィルターを実装しました。footの指定を一般accessより優先し、徒歩向け一方通行を扱います。未解決の条件付き制限・障害物・矛盾するタグは確認待ちとして探索から外します。通常の車向けonewayだけでは徒歩を一方通行にしません。詳細は [PoC検証記録11節](docs/poc-route-map.md#p2-04) を参照してください。

## 経路候補を再現する

~~~text
npm run route:report
~~~

サーバー不要で区間ごとの道路ID・ノード列・距離・参照との共通区間を出力します。固定訪問順は三崎港 → 海南神社 → 光念寺 → 本瑞寺 → 三崎港。合計約1.027km、時速4kmの仮定で約16分です。坂・階段の減速、待機・休憩・撮影は含めません。到着点は既存道路ノードの仮置きで、バス停周辺の基準点は道路中心線上です。現地で操作・待機する位置を示していません。

/poc の画面で区間を選ぶと重なる往復を確認でき、手動参照の表示を切り替えられます。生成候補は距離最短で、交通量・坂・景観を考慮した推奨経路ではありません。手動参照と異なる区間の通行条件は確認待ちです。

固定データは [data/misaki](data/misaki/README.md) に出典・取得時点・クエリ・SHA-256とともに保存しています。**© OpenStreetMap contributors / ODbL 1.0**。起動・テスト・ビルドは外部の道路APIや地図タイルに接続しません。手動参照は同じOSMデータから生成前に固定した机上候補で、現地確認済みの正解ではありません。

データ更新が必要な場合だけ、出典・条件を確認して `node scripts/fetch-misaki-osm.mjs --refresh` を実行します。通常の再現確認では取得し直さず、コミット済みデータを使ってください。更新後は到着点・手動参照・経路を再検証します。

## 分岐と進行方向の検証

~~~text
npm run junction:report
~~~

固定データから分岐候補・接続する枝の道路ID・進入/退出・北基準の方位角・進入方向からの相対角・次候補までの距離をJSONで出力します。生成経路は31候補、手動参照は35候補です。開始・終了・到着点を含み、同じ地点を再訪する場合は通過順ごとに別件として数えます。

/poc の「選択コマの道路接続を照合する」で生成/参照と通過番号を切り替え、全体地図の位置と根拠表を確認できます。角度は各地点の直近の道路ノード間から計算し、進入方向はその地点へ向かう向き、枝は外へ向かう向きです。徒歩の候補・除外・保留を区別し、探索に使えない枝も元データ上の接続として残します。

次候補までの距離は、今回の仮の測定定義として通過位置から次の候補・到着点まで道路形状に沿って累積します。P2-06で進入方向を下・候補の省略なし・元の局所形状を保つ表示を承認済みです。精度の許容値・将来の省略/統合規則は未決定です。詳細は[PoC記録12節](docs/poc-route-map.md#p2-05)を参照してください。

## コマ地図の表示と再現

/poc のコマ図を「前のコマ」「次のコマ」または選択欄で切り替えます。黒点の道から入り、緑の矢印の枝へ進む表示です。進入する向きが上になるよう回転し、出発は退出方向が上、終了は退出矢印なし、折返しは同じ枝へ戻す矢印にしています。

候補は省略・統合せず、元の道路の曲がりや枝を残します。各枝の描画は30m以内か、次の分岐・終端までの模式図です。「次のコマまで」の値は図の長さではなく元の経路に沿う距離です。チェックポイント・経由地・出発/終了には対応スポットを表示します。施設写真は未登録、閲覧操作は達成記録にはなりません。

~~~text
npm run koma:report
~~~

描画点列・元の道路区間・出典/ODbL・確認状態をJSONで再現できます。生成経路は31/31コマを描画できます。比較用の手動参照は35件中25件を描画し、近接分岐で記号を区別しにくい10件は図の確認待ちとして残しています。形状を推測したり、未完成の図を完成扱いにしたりしません。

表示方針の承認は[ADR-003](docs/decisions/003-koma-presentation.md)、検証と残課題は[PoC記録13節](docs/poc-route-map.md#p2-06)を参照してください。現地の接続・入口・最新規制・横断・安全性は未確認で、散策用の公開承認は得ていません。

## 運営者向けの照合PoC

/poc の画面は、将来の管理者側で行う「生成結果の確認」を試すものです。スポット編集・保存・認証・公開を備える管理画面はまだ実装していません。

- 青い点は選択中のコマ、青い線は次のコマまでの実際の道路点列です。GPS現在地ではありません。同じ地点の再訪は別コマで保持し、地図の同じ点を押すと再訪順に切り替わります。

- コマの目印は30m以内で標識/停止点・信号等を優先して最大4件、建物は境界が35m以内等の候補から最大12件。施設の面内の表示点は入口ではありません。未登録の情報・安全性・営業状況は補完しません。

ルート探索はDijkstra法、分岐・コマ生成は元の道路接続と座標の計算です。生成AIは使用していません。同じコード・固定スナップショット・地点順・設定から同じモデルを再計算し、テストでも一致を確認しています。固定PoCの訪問順と仮の到着点は人が指定しています。作業中の下書きも運営者の並びを使い、順序の最適化は採用しません。近傍道路の接続候補は自動計算できますが、入口・現地安全性の自動判定は行っていません。OSMを更新したり地点・条件を変えたりすれば結果は変わり得ます。

~~~text
npm run review:report
~~~

経路、全コマ、補足情報、道路/目印の固定データの出典・ハッシュをJSONで出力します。既存のkoma:reportは道路形状の確認用として引き続き使えます。[追加PoC記録14節](docs/poc-route-map.md#p2-06b)と[直接表記の15節](docs/poc-route-map.md#p2-06c)に検証結果と限界を記録しています。

目印は番号を使わず、信号・バス停・神社・寺院・駐車場等の記号と施設名を図に直接表示します。正式名称は詳細欄からも確認できます。コマ自体の順番を表す番号は維持します。

「止まれ」の標識コードと、OSMの一時停止点を区別します。現在の生成コマ#6・#12・#26では、既存データの停止点を破線の「停」/「停止点」で示します。物理標識の追加取得は公開APIのタイムアウト/502で未完了で、標識の実位置・対象方向を確認したものではありません。対応コードが明示されたデータでは赤い「止まれ」記号を描けます。

### 生成結果を保存して開き直す

/operator/previewの「この結果を保存」で、表示中のルート・全コマ・目印を保存し、保存済み詳細へ移ります。運営者ナビの「保存済みコース」（/operator/courses）から、保存した複数コースを選べます。作業中の下書きは今までどおり1件です。

保存済みは当時の計算結果を表示し、後の台帳/下書き/道路変更を自動反映しません。コマ選択・地図連動・補足レイヤー・拡大/30m参照図を使えます。再読込みやサーバー再起動後も同じIDで開けます。同じ結果の再試行では重複せず、別の結果は追加保存します。

表示後に条件が変わった場合は保存を止めるので、最新内容から再生成して確認してください。通信/保存失敗では画面の結果を残します。すでに成功した保存の応答だけが失われた場合は、再試行で元の保存を開きます。

既存のSPOT_DB_PATHを共用します。現在はSQLite v7で、旧版の編集/削除・下書き/補正・保存済み/公開情報を保持して移行します。保存形式はv1、1件最大8MiBです。更新前のDBはアプリを停止して別途バックアップしてください。未対応/破損した記録は勝手に初期化しません。SQLiteと.env.localをGitへ含めないでください。

保存時は未掲載・現地未確認です。参加者への公開は保存済み詳細で明示実行します。保存済みの編集/削除/下書きへの復元は今回含みません。[保存の検証記録16節](docs/operator-app.md#p4-06b)と[公開の検証記録20節](docs/operator-app.md#p4-06e)を参照してください。

### 保存したコースを参加者向けに公開する

承認済みの[公開仕様](docs/publication-plan.md)に基づき、ローカルアプリ内の公開→参加者開始/コマ閲覧を実装しています。AWSアカウント・認証情報や新しい環境変数は不要です。

2. 「参加者向けに公開」→対象名/保存版/掲載先を確認→「この内容を参加者側に公開」を押します。保存しただけでは掲載しません。

公開停止/同じ内容の再公開を利用できます。内容の一括差替は未実装です。最後のコマでは写真提示を案内し、到着/撮影や受付/終了を自動認定しません。CP0件も開始/閲覧でき、写真提示を要求しません。現地確認/受付運用・一般向け配信/AWSは後続。QR/AI認証・クーポンは対象外です。[参加者画面8節](docs/participant-app.md#published-participant-flow)と[ADR-018](docs/decisions/018-published-participant-courses.md)を参照してください。

### 公開を停止・同じ内容を再公開する

コースは運営者がスポット/経由地・訪問順を選んで生成し、公開時点で固定します。以前の説明の「可変」はこの作成したコースの意味で、参加中に道順が変わる追加機能は想定していません。

/operator/coursesから対象を開き、「公開を停止」→対象名/影響を確認→「このコースの公開を停止」で一覧から外します。開始済みの人も次回読込から閲覧できなくなります。保存済みコースと開始記録は残し、停止中の詳細から「同じ内容を再公開」を確認/実行できます。

再公開した同じコースでは、同じタブに残る元の参加ID/開始日時を引き継ぎます。停止前に開いた詳細からの開始/再開も、公開状態を再確認します。開いたままのコマは再読込まで残り得ます。即時の遠隔消去や常時監視は行いません。

保存失敗では変更済みと表示せず、応答が失われても同じ操作を再試行できます。他画面で状態が変わった場合は開き直して確認してください。内容を変えるときは、下書きのスポット/経由地を選び直し→再生成→確認→別保存し、新コースの公開と旧コースの停止をそれぞれ実行します。既存の公開版や参加記録を自動差替しません。

[仕様/検証記録22節](docs/operator-app.md#publication-controls)と[ADR-019](docs/decisions/019-course-publication-controls.md)を参照してください。現在のDBはv7で、旧版の行/公開日時を保持して移行します。更新前のバックアップはアプリを停止して保管し、旧コードへ戻す場合は対応するバックアップを使用してください。

### 写真を撮って巡る参加者画面（要件v0.3）

一覧のカード構成を保ち、独立詳細ページを省いて開始→コマへ進みます。コマ画面は地図・番号・前後ボタン/スワイプを中心にします。コースタイトル/地点一覧・開始日時・次のコマまで/累積の距離は常時表示しません。右上の見方ボタンから凡例・安全案内/出典時点、レイヤーと番号だけのコマ選択を確認できます。OSM帰属は残します。

チェックポイントの該当コマで「○○です。写真を撮ろう」と案内します。各自のスマホカメラで撮影し、ゴールでスタッフ等に見せてください。アプリにカメラ権限/画像の提出を求めず、撮影済み・到着済みや画像枚数を判定しません。最後のコマは写真提示の案内で、終了記録を自動保存する機能ではありません。

先のCP名を選択肢/地図ラベルから伏せ、コース名や開始/終了名に含まれる登録名も参加者向け表示で伏せます。元の保存値や運営者の名称/距離・図形は維持します。手で先に進むことやデータの閲覧/別名からの推測を防ぐ機能ではありません。

開始は同じタブの既存記録を引き継ぎます。再読込みでは閲覧コマだけ最初へ戻ります。公開停止/再公開の制御を維持し、SQLite/保存形式・依存や環境変数は変えません。[参加者画面11節](docs/participant-app.md#photo-walk)と[ADR-020](docs/decisions/020-photo-walk-participant.md)を参照してください。
